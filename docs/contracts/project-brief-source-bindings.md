# Declared ProjectBrief repository sources

This bounded slice retains `r3:scope-profiles` / `journey-scope-profiles`, `v2:identity`, `v2:selection`, `v2:evidence` and `r2:facets-search`. It does not qualify the full multi-organization or account-inventory scope.

The existing `diagramcloud.project-brief` version 1 accepts explicit repository IDs and `scope[].repositoryIds`. Compilation now creates one private Project source per repository, with ID `brief-repository-<repository id>`. Renaming labels or reordering declarations does not change these IDs. Two scopes can reference the same source; homonymous repositories with different supplied IDs remain distinct. No name matching, repository read, runtime observation or mirror inference occurs.

Bindings use the existing canonical evidence grammar: `Project.nodes[].blockIds` points to `brief-meta-<scope id>`, whose `sourceIds` includes the author declaration and the unique explicitly bound repository sources. These private text blocks retain `provenance: author`. They describe membership declarations, not source-derived findings. The separate existing manifest remains acquisition input for the Atlas.

The node's own `sourceIds` stays `['project-brief-source']`. Repository membership does not claim that the authored caption came from the repository. This preserves the existing public-caption rule: after an author explicitly publishes the declaration source and node, a private repository binding does not erase that caption. Binding evidence and repository metadata remain private. Publishing an evidence block alone cannot expose its private sources; both the relevant sources and evidence need an explicit publication choice. The compiler makes none of those choices.

Source citations contain the supplied host, repository ID and safe remote HTTP(S) locator or forge shorthand when available, plus a safe declared ref/revision. Credential-bearing locators are rejected by the existing validators. Local acquisition paths, local locators, unsupported locator schemes, query/fragment locators and absolute, traversal or control-bearing refs are omitted from citations. Normal branch refs such as `feature/orders` remain valid. These omissions do not establish a missing repository or changed identity. No source URL is fetched. The manifest retains its explicitly selected local path; that path never enters the compiled Project.

Compiling without repositories retains its prior behavior. Compile creates a new review candidate; it does not replace an edited Project. The existing conservative reimport keeps authored labels, captions, evidence and sources. Newly added scope blocks receive their declared bindings, but existing evidence blocks are not silently rewritten when incoming bindings change. Updating that retained evidence needs an explicit reviewed patch. This slice adds no automatic binding reconciliation, global repository registry or usage-accounting format.

The [synthetic shared-repository example](../../examples/project-intelligence/shared-repository-brief.json) uses two logical scopes and two same-title repositories on different forges. Its revision strings are declared fixture values, not inspected commits or verified deployment claims.
