# Browser-local Studio panel layout

The existing canonical sidebar (Navigator, Inspector, gallery and Story together) can be placed left or right. The explanatory Details panel occupies the opposite side when open. This changes CSS placement only; the components retain their DOM position and React lifetime. Keyboard reading order remains sidebar, main, Details. The editable Inspector still targets the active selection; a pinned explanatory context never becomes the Edit target.

`Hide sidebar` / `Show sidebar` and `Hide details` / `Show details` retain mounted components and their navigation filter or Pin. The generic recovery controls remain outside every hideable pane and are available with Vanilla, Standard and Advanced profiles. `Open details` opens the existing panel. Existing `Close details` still unmounts it and resets Follow, as documented by the Follow/Pin contract. Collapsing is a separate action and does not close it.

Native labelled width sliders provide keyboard adjustment. Requested sidebar sizes are 220–420 px, Details 260–480 px. Effective desktop widths are clamped against the current workspace, reserving at least 360 px for the main column. At 1200 px or narrower, panes stack at full width, ignoring desktop placement/widths while retaining those session choices for a return to desktop. Disabled compact controls label their values as desktop requests, including in accessible value text, rather than claiming those numbers are current effective widths. The selected IDs, parent path, current revision and source facts never change during a layout action.

This deliberately changes the tablet layout. Previously, without Details, the sidebar and main stayed in two columns down to 800 px; now widths from 801 through 1200 px also use the full-width stack. Previously opening Details hid the sidebar at 1200 px and below, and also hid the main workspace at 760 px and below. The new stack keeps every non-collapsed pane available. Reset uses these new responsive defaults; it does not restore the former tablet hiding rules.

Placement and requested desktop widths are opt-in browser-local preferences. `Save placement and widths` writes one bounded version1 localStorage record scoped by the existing encoded host/project tuple. No Project, IndexedDB schema/store or strict presentation-profile v1 record changes. Ordinary moving, resizing and collapse do not save automatically. Reopening or changing project/host reads only that scope's saved choices; absent, unreadable or unsupported preferences show defaults without deleting or repairing stored bytes. Blocked reads/writes show a generic session-only notice without echoing supplied text.

Only side and requested widths persist. Collapse, Details opening, Pin/Follow, selection, paths, filters, modes and effective pixels stay temporary. `Load saved placement and widths` explicitly overlays only those three physical fields; current collapse and explanatory context remain unchanged. Reload starts panels expanded and Details closed, so a saved preference never revives a hidden private Pin.

`Reset workspace layout` resets the current placement, requested widths and collapsed flags. When a saved-layout record already exists, this explicit action also replaces it with default placement and widths; its visible copy says so. Without an existing record Reset creates none, preserving opt-in behavior. If storage cannot be read or written, defaults apply in this session with an explanation. Reset never selects another component, closes Details, resets Pin, changes profile or analysis/source/publication choices, or edits the Project.

Cross-tab UI saves are deliberately last-explicit-save-wins, not atomic compare-and-swap and not the canonical Project conflict transaction. A scoped storage event shows a generic notice; it does not reflow active panels or parse/display another tab's values. The author may explicitly load saved choices or save the current ones. Simultaneous explicit preference writes can replace each other. Canonical IndexedDB generation guards, quarantine, backup and save queue remain unchanged. Saved layout is lost when browser site data is cleared; Project JSON/public exports do not carry these preferences, and no host or cloud synchronization is implied.

Hidden panels continue to receive the permitted projection. Portfolio/Present redacts and revokes a private Pin even while collapsed; revealing the panel or returning to author mode cannot revive a revoked private target. No private labels are used in recovery controls or layout state. Authoring JSON and public exports carry no layout fields.

This is a local Web slice of `r2:workspace-layout`: original acceptance requires navigation/Inspector left/right, collapse and sizing, with bottom optional. The source criteria are retained in the ignored preparation plan. The existing sidebar moves as one panel; separate docking of Navigator and Inspector, bottom docking, semantic saved views/bookmarks, Hub/PM/VSIX compact/full transport and host workbench settings remain open. Browser-local saved placement/widths do not close those clauses. No host capability or exact-commit CI qualification is implied.

Proposed validation: pure finite/bounded layout tests; actual synthetic reviewed import, keyboard show/hide and widths, both placements, retained Pin/filter/parent, canonical Edit target, all presentation profiles, hidden/public privacy, reset, project/reload scoped restore and temporary-context reset, unrelated storage byte preservation and 390 px screenshots. ## Semantic session return stays separate

Existing Back/Forward also captures the visible output sheet and selected connection, retaining the existing 50-entry session cap and forward-branch behavior. It is not authoring Undo/Redo. Every restore resolves against the current already permitted document: the whole recorded path starts at root, has valid direct parent-child links, and contains the active view with its selected component or edge membership. The active view may be an ancestor of an already open child. A new selection in root still deliberately truncates descendants; history does not override that action. The permissive `pathToView` fallback cannot establish reachability.

Project and author/public boundaries reset transient history synchronously. A revoked/deleted/out-of-membership target produces one generic unavailable notice, leaves the current visible target unchanged and prunes only that session entry so another return is possible. It never redirects to a different membership, revives a private Pin, changes mode/purpose, or restores old source facts/revision/observations. Valid IDs after a document revision change open current facts. Restoring navigation stops transient story playback but never edits authored story or its human evidence decisions. Repository context is still derived from selected ID/active view, not a separately replayed scope.

History remains memory-only, independent of physical layout, filters, Pin/Follow and source/analysis/publication configuration. There is no Project mutation, canonical save, new store/schema, browser-history protocol or hidden preference migration. `layout.v1` and strict presentation-profile records retain their existing meanings. Existing validated views/story remain the durable document semantics; this does not complete named saved views/bookmarks or installed host context transport.

Qualification must preserve earlier perspective tests and exercise visible-sheet/edge returns, selected parent plus retained child, deleted targets, source/current-revision membership, public/project reset, unchanged Pin and canonical stored row/preferences, keyboard/390px and ordinary imports. Prepared payloads/syntax alone establish no runtime PASS; all eight workstreams remain PARTIAL.


## Existing canonical view text authoring

`ProjectView.title` and `description` remain the only durable fields in this slice. Studio Edit supplies an optional Canvas callback; the public React consumer supplies none and receives no authoring controls. The local draft is masked synchronously when its project/view/revision/context changes, cleared on that boundary/unmount and never stored. Apply/Cancel/Escape are explicit native form actions. Title must contain non-whitespace text within the existing 1–160 bound; description keeps its native 2000 bound. Valid strings are preserved exactly, with no truncation or automatic trimming.

Immediately before Apply, Studio reads `historyRef.current.present`, checks exact captured Project ID/revision, the live Project object identity, context epoch, Edit mode, live diagram/non-Design context without a modal/task workspace, and displayed stable view membership. A missing/stale target is refused generically, with no fallback or partial edit. The epoch also invalidates same-ID/revision document replacement and leaving/returning to an earlier context. Full canonical validation precedes one existing `change`/commit/save; one Undo restores both strings. No-op Apply, Cancel/Escape and rejected input create no history/save entry.

This does not alter IDs, node/edge/view membership, positions, perspective/design/visibility, child links, source facts/citations, observations, story, Pin, physical preferences, source modes or acquisition. Existing IndexedDB/queue/conflict handling, reviewed import and authoring backup remain the persistence path. Public projection excludes private/unreachable views; editing explanation does not change visibility or confer source permission. No new model, database, purpose enum, host protocol or saved-bookmark format is added.

Prepared synthetic journeys cover root/child text, exact unrelated-field equality, blank/oversized rejection, Cancel/Escape/no-op, one Undo/Redo, save/reload/backup/reviewed re-import, stale revision/view/mode/project/delete boundaries, native keyboard390px, parent retention/Pin and private/public output. Tests are not executed by proposal preparation. The original library/navigation/simple-mode clauses remain PARTIAL, including complete saved semantic views and cross-host context transport. The existing short-edge label occlusion and overlapping parallel interaction bands remain OPEN renderer risks; widened session fixtures qualify semantic return only.


## Native placed connection-label selection (bounded proposal)

Normal Studio visible, routed, nonempty placed connection labels use a native `type=button` only when Canvas supplies its optional local activation closure. The accessible Select connection name includes canonical ID and full label; visual text, title/data-full, measured width/16px height/transform, clipping and routes are preserved. Enter/Space use native button semantics. The click stops propagation and forwards the existing `onEdge(edgeId,viewId)` exactly once; it does not change Project facts, positions, view membership, source proof or authority. Narrow inline native-button resets preserve existing CSS/measurement without changing global or SDK styles. A current-input/visible-membership/live-drag/unmount guard rejects retired actions.

Edit selection opens the existing connection editor. Explore selects/highlights through the existing path; it does not acquire a new complete read-only edge inspector. Hidden/no-space/unlabelled/live-drag labels remain inert, with the permitted Relationships table as an alternative. Collapsed projection still selects original assertion ID, never creates a new relationship. Endpoint source citations are context, not relation proof.

Strict controlled React viewers retain the original span path: the optional closure is absent, no new label button/callback/editor/source access exists, and existing host-controlled intent/revocation rules remain unchanged.
