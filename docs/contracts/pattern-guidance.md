# Authored pattern and recipe guidance

This is an additive internal content contract on the existing `patternSchema` and `recipeSchema`. It is not a Project format, a pack importer, another catalogue store or an execution interface. Existing entries without `guidance` remain readable with their stable IDs and native `version: 1`. Detailed guidance preserves pattern `medallion` (topic `lakehouse-medallion`) and recipe `jobs` (topic `spark-production`), with additive cards for existing patterns `c4`, `modular-monolith` and `event` (topic `event-driven`), plus pattern `migration` (topic `migration`). Other entries explicitly lack the detailed card. These six cards do not complete the 64-topic catalogue or V2.

`guidanceSchema` bounds nonblank content, arrays and documentation citations. `PatternGuidance` contains a topic key, authored content revision, `basis: authored-illustrative-guidance`, `applicability: UNKNOWN_NOT_ASSESSED`, packet review date, problem, conditions, contraindications, alternatives, tradeoffs, macro/medium/micro questions, limits and sources. Statement `sourceKeys` refer only to that card's static documentation records; unknown or repeated references and duplicate source keys are rejected. An empty source-key list identifies authored educational reasoning, not a provider claim. A citation does not prove the whole statement or grant permission.

Dates and identities stay distinct: `contentRevision` identifies our authored text; `packetReviewedOn` is the handoff research date; `retrievedOn` records the bounded primary-page read; `pageUpdatedOn` is optional provider metadata; `externalRevision` is the exact revision only when actually known, otherwise `null`. No external content hash or commit was collected for the five pages. The current records therefore retain UNKNOWN external revisions. A page date is not an installed runtime version or a compatibility claim.

The medallion card contrasts refinement responsibilities with deployment environments and asks for contracts, consumers and transformation evidence. Its small direct-pipeline alternative is authored conditional guidance, not a vendor exemption or a requirement that every project use three physical stores. The jobs card compares orchestrated notebook, package entry point and conditional SQL routes. It gives no absolute notebook/job verdict, performance/cost/reliability ranking or runtime result. All workload applicability is unassessed.
