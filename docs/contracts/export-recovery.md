# Export recovery without unrelated artwork fetches

The existing export dispatcher uses downloaded registered IconData only for artwork fidelity JSON, SVG, PNG, Interactive HTML, Editable PowerPoint and Project deck. Those six existing branches retain the same public projection, active-view fallback, icon loader and producer arguments. Provider artwork stays exact and under its separately recorded terms. No renderer, slide layout, icon registry, asset bytes or font changes are part of this slice.

Other current formats do not consume those downloaded bytes: Business Overview HTML, Public JSON, Authoring JSON, Mermaid, Blueprint/Editorial SVG, Diagram Design figure/deck/book, Technical Manual, ConceptSpec, ViewSpec, AtlasNote, draw.io and Portfolio index. They use the existing `noIcons` fallback at the dispatcher and do not wait for unrelated icon retrieval. Their own producers and data boundaries are unchanged. This is a local control-flow correction, not a new export engine, format registry or network manager.

In particular, **Download backup** from the local-save-error alert calls the same dispatcher with Authoring JSON. It must preserve the exact current in-memory document, including private and unattached fields, while unrelated icon retrieval is still pending. **Public JSON** still serializes only `publicDocument(project)`. A backup is an explicit full private recovery action; it is never a public publication. Removing an unused asset dependency does not grant a new audience or destination.

`loadBrowserIcons` continues to fetch registered same-origin files for visual consumers and embed their original bytes. Completed failures still use its existing semantic fallback. This change does not add a deadline/cancellation mechanism for visual exports: a stalled visual icon request can still delay that visual export. It does not bypass publicDocument, invent artwork, activate cloud/owner services, or change output success messages and unknown-format behavior.

The prepared browser counterexamples use only a synthetic Project with a reachable public registered icon and a synthetic private sentinel. A real controlled fetch remains unresolved until cleanup while a storage-quota edit and exact Authoring JSON backup complete. The test checks pending state before cleanup, and never fulfils that request to make the backup assertion pass. Cleanup explicitly aborts the held routes and awaits the test-owned fetch promise. Public JSON compares exact existing projection bytes and proves no export icon fetch. A separate SVG positive control intentionally releases the exact existing registered public icon file, then checks its base64 bytes and public redaction; it neither modifies nor copies that artwork into the proposal. Existing storage/conflict tests and their timeouts remain intact.

This addresses a bounded local portion of retained `v2:interop-assets` and recovery/storage/offline journeys. Original r3 delivery-lineage and r4 public/author/publication boundaries remain exact. Separately scoped private visual export, full installed-host qualification, output signatures, actual remote CI, merge/deployment/redownload and authorized external publication remain open. All eight workstreams remain PARTIAL. A prepared patch or parser result is not a qualified artifact, owner approval or delivery grant.

After reviewed application, root runs actual source-bound TypeScript/unit/build/browser gates and inspects synthetic recovery evidence. Existing icon/artwork, public export, HTML/offline and PPTX structural regressions remain relevant. This slice intentionally avoids visual producer/layout changes; if later corrections alter visual inputs or output bytes, actual native PowerPoint review is required instead of inferring it from ZIP validity. No runtime qualification is asserted by this contract.


## Supplied quantities in printable manuals (next bounded proposal)

The existing Technical Manual remains static HTML printed by the browser; the Diagram Design CLI already produces offline PDFs. This proposal repairs the manual connection ledger, without adding another exporter or PDF engine. A compact chapter retains the full stable connection ID and a quantity detail cell with the exact supplied value, unit, canonical provenance and optional note. Known zero is printed as `Amount: 0`; a missing quantity says `Not supplied`. Values are not summed, units and notes are not normalized, and synthetic, source-derived, reference and author declarations are not promoted to measured or verified results.

Dense full connection and keyed cross-page tables retain their current ID/Amount/Unit/Provenance columns and add the supplied note. The same public ViewSpec still controls membership and original-input omissions. Endpoint sources do not become edge citations. Quantities from private or excluded views, private endpoints or connections never enter the public manual. The manual uses the existing escaping helper and native named tables; connection cells wrap full text locally, and printed connection tables may split between rows. Other figures, scene routes, page planning, model fields, observations, authoring JSON and immutable-publication inputs are unchanged.
