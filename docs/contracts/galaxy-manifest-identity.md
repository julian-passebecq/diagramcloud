# Galaxy manifest source-identity boundary

The existing Galaxy-map reader in `src/core/atlas/manifest.ts` consumes the supported subset of the Claude Control-owned format. It does not define or write that owner's format, discover repositories or grant permission to import, scan or publish them.

Repeated exact `apps[].id` values are ambiguous for this consumer. The reader refuses them before local ID suffixing or endpoint resolution, with the fixed error `Ambiguous Galaxy app identities. No project was created.` It does not echo source IDs, names, paths, locators or JSON; choose or correct an unambiguous authorized source before retrying. Repeated identical rows are also refused, rather than interpreted as shared membership.

Different source IDs may have the same display name. They remain different declarations. Existing distinct-ID slug collisions still receive different local suffix IDs, and connections resolve through the supplied exact source ID within that input. This does not establish persistent identity across reordered collisions, a mirror/alias relation, cross-project ownership or many-to-many membership. Those require a separate explicit contract and compatibility decision.

Unknown connection endpoints and self-loop omissions retain their existing notes. Native ProjectManifest and DataPass readers, source status meanings, repository remotes and source evidence are unchanged. Reading a map remains a declaration, not a scan or an external runtime observation. A candidate still needs the existing native validation and human import review; a rejected parse cannot become an applied replacement.

This bounded guard advances the negative identity/collision case of the original `v2:identity` / `choose-scope` criteria. It does not qualify a private Galaxy client, provider inventory, canonical shared membership, aliases/mirrors or installed consumer parity. Synthetic test cases do not become real observations, and no owner, access or publication authority follows from format support.

## Explicit supported Galaxy scope

The native ProjectManifest capacity remains 40 repositories. A Galaxy declaration with more than 40 apps is refused with the fixed message `Galaxy scope exceeds the supported limit of 40 applications. Select a smaller explicit scope. No project was created.` The reader no longer returns an unreported first 40 subset, or lets a relationship to the excluded app fail later as an unknown repository. This is the existing consumer capacity, not an upstream owner constraint or an inventory/access count.

The capacity admission precedes local identity allocation, membership materialization and connection resolution. For an overcapacity declaration it also precedes the exact-duplicate check, so a duplicate outside the first 40 cannot disappear through truncation or change the constant capacity message. Within the supported capacity the prior exact duplicate refusal is unchanged. Normal JSON/source-structure parsing still occurs first. No names, raw/normalized IDs, paths, locators or source bytes are echoed by this capacity error.

All supported inputs retain their existing local IDs, ordering, homonymous names, relationships and statuses. In particular, an explicit 40th app and connections from/to it are retained. Native manifest and DataPass routes retain their current formats/limits; no source is rewritten. Existing Project documents still load and no historical references are migrated. A previously silently partial overcapacity conversion now requires the author to provide a smaller explicit scope, instead of being described as a complete successful import.

This guard does not stabilize suffix IDs across reordered slug collisions. Original raw Galaxy app ID→local repository mapping is ephemeral, and older atlas snapshots do not carry enough source provenance to recover it universally. Sorting/hashing/rekeying old IDs from labels/remotes/paths is not authorized by this correction. Such a migration needs exact prior source/mapping evidence and a separately reviewed compatibility decision; a native explicit manifest is the existing human route for stable IDs.

Prepared truth cases cover 40 accepted with final-app links, 41 with/without excluded endpoints, order permutations, overcapacity duplicates, existing <=40 duplicate rejection, unchanged native capacity, input nonmutation, no scan/guessed revision and zero observations. Parser/syntax preparation is not runtime qualification. All original Core/Galaxy/shared membership/client/host clauses remain PARTIAL/open; no owner format, source access or publication grant follows from this local capacity limit.

## Opt-in forward import provenance

The existing converter can optionally retain one bounded private receipt for the newly composed input. This is consumer-local `diagramcloud.galaxy-import-provenance/1` metadata inside the existing code-evidence grammar, not a Galaxy owner format, canonical schema extension, database, namespace grant, observation or ID-reuse API. Default conversion remains unchanged and no receipt is captured without explicit opt-in.

In the existing Gallery manifest picker or New analysis → Hybrid, `Capture private Galaxy import provenance` applies only to a new local Galaxy project. The option resets off on project/revision, mode, modal or analysis-source changes. Preview and human Apply stay separate. An existing `atlas-galaxy` project does not establish a common source namespace: capture is unavailable there, with a generic explanation in the review; the existing import/merge behavior continues. No new target ID, source selection, historical replacement or automatic binding is introduced. Pending capture is ignored after cancel, context change or newer work.

The CLI accepts an explicit boolean flag:

```text
npm run atlas -- selected-galaxy.json --capture-galaxy-provenance --out private-atlas.json
```

This flag captures only the newly composed input. `--previous` still retains snapshot history and comparison, with the same scan behavior; it never supplies source scope, prior mappings or reused IDs. Reading/importing never rewrites `galaxy.json` or scans an account. Full authoring output includes private metadata; review the destination before sharing it.

The one private code block uses reserved ID `analysis-galaxy-import-receipt`, is linked through repository-card `blockIds`, and adds no ordinary source citation or node-caption `sourceIds`. The receipt contains only consumer parser/version, target local Project/snapshot IDs, import capture time, exact raw source app ID → allocated repository/node ID pairs and input digest metadata. It copies no names, remotes, local paths or extra raw source fields solely for identity. `namespace: null`, `bindingState: unbound`, `synthetic: null` and upstream version `null` are explicit unknowns. Mapping provenance is source-declared; capture time is not an observed/runtime time, and parser/version is not the owner's source version.

`input.digestDomain: decoded-text-utf8` and `input.sha256` identify the exact UTF-8 encoding of the decoded input string used by this import, including its whitespace. They do not identify original file bytes/encoding, reserialized JSON, repository Git revision, source authenticity, organization scope, a build or deployment. Re-encoding replaces unpaired surrogates according to TextEncoder; this is the stated text domain, not a claim of byte-for-byte original-file preservation. Repository revisions stay in their existing snapshot fields. A legitimate content change cannot establish or revoke a source namespace.

A strict local codec requires complete unique mappings (at most 40), unchanged exact nonblank source IDs (at most 1,000 characters, without control characters), valid existing repository/node IDs and the exact `repo-<repositoryId>` association. Source IDs are inert strings: no normalization, evaluation, path navigation or instruction interpretation. The serialized receipt must fit one code block (at most 48,000 characters and 64 KiB UTF-8); the input text domain is at most 1 MiB. Sensitive metadata is rejected through the existing secret detector. Existing reserved receipt evidence is not overwritten, and mismatched candidate repositories cannot receive a capture. Failure gives only `Galaxy provenance capture unavailable. The normal import is unchanged; no IDs were reused.` The normal candidate is returned untouched; no truncated/sanitized partial mapping is presented as complete. Native validation, source admission and duplicate-ID errors remain their existing boundaries.

Private evidence is not a secret storage service. Authoring JSON deliberately retains it. `publicDocument` forces all `analysis-galaxy-import-` evidence private before publication, even if its visibility was changed, so private mapping text/digest/metadata is excluded from public closure and counts. Exporters keep using that public projection; existing already-public IDs/locators/facts are unchanged. Moving private source references onto ordinary node captions would change the public-caption rule and is not done here. The receipt is editable/untrusted; strict parsing and digest consistency are not producer authenticity or human authorization.

No reader reuses captured IDs. Historical imports with no receipt stay unchanged/UNKNOWN, and sorting/hashing/rekeying cannot repair them. A later same-source continuity proposal must require explicit prior Project/receipt/namespace review, target revision/digest guards, reserved historical IDs and noninterference across organizations/projects. Current same-ID library lookup and `--previous` cannot provide that grant. Current connection IDs also use `rel-N` order: repository provenance alone cannot preserve reordered relationship identity, author evidence or removed facts. That later merge/migration policy remains open, as do shared membership, mirrors, installed hosts and private client acceptance.

Prepared qualification includes exact text-digest/mapping truth cases, representability/sensitive-data/collision refusals, forced public-redaction/noninterference, real CLI default/flag/history, normal UI opt-in/private backup/reopen, mobile selected-file opt-in, explicit existing-project unavailable state, offline public HTML and cancelled late digest. A syntax-only preparation is not execution of those tests, a runtime PASS or an owner adoption claim.

While App analysis is busy, the main ProjectBrief/manifest JSON editor is read-only, remains focusable/selectable for copying, and keeps its actual draft. Cancel analysis stays enabled; it invalidates the pending generation and unlocks edits, so a new draft cannot be replaced by the old digest result. This read-only condition is only App busy: selected-file reading and local graph preparing retain their prior editable/cancellable semantics. The CLI prints exactly one explicit capture outcome line when its opt-in flag is supplied; the ordinary report lines/default-off output are unchanged.
