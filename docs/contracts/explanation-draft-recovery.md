# Private explanation draft recovery

**Edit → Tours → Author explanation → Private draft recovery** is optional browser-local persistence for an unfinished request. **Autosave this private draft in this browser** is off on each new form session. Checking it saves the current draft and subsequent changes. Reopening or reloading never silently replaces the form: **Recover saved draft** is explicit. A matching confirmed saved copy lets the dialog close without an unsaved-work warning; edited/failed/conflicting forms retain the close/download guard. Turning autosave off does not delete an existing copy. **Delete saved draft** removes only that copy, not the current form. A copy also remains after Review or Apply, retaining its old source basis; delete it explicitly when no longer wanted.

The single slot is keyed by the exact browser host, Project ID and `author` audience using `diagramcloud.explanation-draft.v1`. Only the private Edit dialog mounts the reader. Public modes neither mount it nor read these records. A project switch pauses operations against the captured scope. The envelope contains the original project ID, revision and fingerprint plus raw request draft fields; it never contains a frozen Project, permission grant, observation, review or execution receipt. Private text and source IDs are readable by anyone with access to the browser profile. This is not encrypted storage or an external backup.

Recovery validation is intentionally different from complete request import: it preserves blank strings, whitespace, incomplete state rows, questions and numeric code ranges without compiler normalization. Supported fields and bounded shapes remain strict; unknown versions/fields, wrong types, duplicate step identities and payload/scope mismatches are refused. The entire record is limited to 4 MiB UTF-8. Recovery is not proof that a request is valid. Existing Review and Apply repeat the source and compiler guards; validated file exchange remains separate.

The original revision and fingerprint are never refreshed. If the current Project differs, recovered content appears as read-only raw request JSON with the existing draft download available; no current labels are substituted for unavailable historical references. Review is disabled. Opening the exact original source permits normal authoring again. The stored record contains no historical source snapshot and cannot reconstruct one.

Saving and deleting compare the exact previously observed stored string before a write and verify the result afterward. A matching storage event stops autosave and reports a conflict; **Refresh saved draft** updates only the observed copy, never the form. Explicit recovery or deletion resolves the choice. Corrupt content remains untouched until explicit deletion. Quota/blocked/unavailable storage reports not saved, stops autosave and preserves the in-memory form and download paths. No automatic retry overwrites a newer record. This uses the existing bounded localStorage preference pattern, not an atomic cross-tab transaction: truly simultaneous reads/writes can race. Site-data clearing, another application on the same origin, profile loss and storage eviction are outside this recovery guarantee.

No Project schema, Undo operation, network request, provider call, public export payload or autonomous execution is added. Raw request draft download and strict validated request-file import/export retain their original contracts. Browser regression covers 1440/390 explicit recovery, original stale binding, conflicting tabs, corrupt/quota handling, private/public transitions and unchanged stored Project; source tests cover scope, payload and storage boundaries.
