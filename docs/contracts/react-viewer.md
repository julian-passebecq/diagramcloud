# Local public React viewer source entry

This is a local DiagramCloud React source-module entry, not a published package or an owner wire protocol. It reuses DiagramCanvas, SceneEdge and canonical Project. It mounts no Studio application, workspace, library, save queue, analysis service or store. It accepts no filesystem, token, command, URI resolver, collection, mutation, reviewed-apply or publication API. The host JavaScript realm already owns its input and authorization; the viewer is not a sandbox against that host.

Import `DiagramCloudViewer`, `REACT_VIEWER_API_VERSION` and the selection/intent types from `src/react`. Supply `apiVersion={1}`, a canonical `document`, a finite nonempty unique `allowedViewIds` array and controlled `selection={projectId,baseRevision,viewId,nodeId? or edgeId?}`. The input is validated with validateDocument then publicDocument before scope/context/rendering. Unsupported version, malformed/private/out-of-scope selection, unknown fields or contradictory node+edge fail closed with one fixed generic message, without echoing validator paths or private IDs.

Callbacks are optional local read/navigation intents: `onSelectionChange`, `onNavigateView`, `onOpenSource`. Their presence advertises only the implemented callback, never a permission grant. Selection/navigation emits only projectId/baseRevision/viewId and optional canonical nodeId or edgeId. Source requests add a sourceId attached to the current selected public context; no location, URI, token, file path or Project accompanies them. Nothing opens automatically. Missing callbacks are visibly unavailable; the host may reject any request by retaining its controlled selection. The canvas cannot select locally in that case.

Viewer-owned controls and the shared card button have explicit `type="button"`, so selecting a card by pointer or keyboard does not submit an enclosing host form. The synthetic consumer embeds both viewers in a real form with a submit counter, explicit positive-control Submit and reset; card clicks, keyboard selection and navigation must leave that counter at zero. This removes an unintended native default action, without adding a host capability.

Public allowed-view closure drops unrelated public/private nodes, exact nonmember edges, sources/evidence/assets and project-global title/summary/readiness/atlas/delivery/history. Workspaces are removed. Child-view metadata is retained only for explicitly granted views; ungranted child and parent labels never render. The existing canonical path helper resolves only within that closure: a reachable granted authored root takes priority; otherwise the longest admitted ancestor path is retained, with ties in canonical view order. No path crosses an ungranted intermediate view, and child-only scope renders only that child. This is transient presentation rooting, not a change to the input Project or hierarchy. Exact view.edgeIds always bounds relations, even for nodes shared with another view.

The visible revision is explicitly the **document revision**, not a repository revision. Every ready viewer displays the same constant omission warning: "Repository revision vectors, deployment/workspace context and custom artwork are not included in this public viewer." This statement does not read atlas, deployment or workspace metadata, distinguish its presence, or count omitted objects.

Selected context on screen is an internal DTO, not a new persisted or external schema. The file fallback reuses createCompletionRequest and completionRequestSchema, with audience public and an explicit component/view selection on a single-view canonical derived closure. It retains the existing 64 KiB budgets, exact selected omissions and secret checks. It emits the existing inert `diagramcloud.selected-context/1` request, never a Project backup; the viewer exposes no response/apply API. Selecting an edge makes file fallback explicitly unavailable. An edge is never silently broadened into a view request. Source opening remains a minimal ID callback; source URLs are never executed by the viewer.

Each viewer uses an independent ReactFlowProvider for each rendered canvas even inside a host provider. Per-instance useId encoded without lossy normalization plus rendered-canvas index separates React Flow IDs; a length-prefixed canonical edge ID creates a DOM-only SVG path ID. Canonical node/edge IDs, routes, scene points, view memberships and callback IDs stay unchanged. React multi-root server rendering must provide distinct React identifierPrefix values, as required to keep useId unique between server roots.

The shared canvas adds optional genericIcons/strictControlledSelection/canvasId seams with existing Studio defaults. NodeIcon bypasses provider/data artwork in generic mode; there is no viewer asset resolver, BASE_URL requirement, remote icon or font fetch. Existing React Flow global stylesheet import moves from Canvas to main.tsx before App so Studio keeps its existing stylesheet order. Viewer CSS is a static copy of the installed React Flow12.12.0 stylesheet with all ordinary selectors prefixed `.diagramcloud-viewer`, its animation name isolated and MIT license retained; local styles are equally scoped. No Studio global body/html/#root reset is imported.

Input reference identity, numeric revision, selection, scope, actual scoped public content, callbacks and unmount are checked at delivery. A clone does not increment a document revision: a new object at the same revision is a valid current input but invalidates earlier captured actions. The host must use immutable document/selection/scope updates. No delayed network or collection work is started. Synchronous intents are not an instruction for a host to apply changes; any future edits require its own existing reviewed patch transaction.

## Host session: explicit capabilities and guarded returns

`src/react/hostSession.ts`. A host may pass `session` (a `diagramcloud.host-session/1` offer: `sessionId`, `audience: "public"`, `grants`) and `onReturn`. Without a session the viewer behaves exactly as above. Negotiation is explicit and read-only by default: granted = offered ∩ implemented. This viewer implements `query` (hands the host the selected public context request, `diagramcloud.selected-context/1`) and `render` (the public SVG of the selected view, drawn by the existing architecture renderer from the already-public closure). `propose`, `validate`, `apply` and `publish` are recognised and always refused with a fixed reason; an unknown name is refused as unknown. A refused offer (wrong format, session ID or an author audience) shows one fixed message and grants nothing. No authoring control, text field or apply path appears in any case.

Every return is a `diagramcloud.host-return/1` intent: one-time `intentId`, `sessionId`, `kind` (selection, navigate, source, query, render), exact `projectId`, `baseRevision`, `audience`, view and optional node/edge/source, and a payload for query/render only (512 KiB at most). Intents are built from the live, revalidated boundary at delivery, so a replaced, narrowed or unmounted viewer emits nothing. `createReturnGuard(binding)` is the host side: it refuses `malformed`, `wrong-session`, `replayed` (an intent ID already accepted, including a file copy of it), `stale` (other project, revision or audience; `rebind` when the document advances), `not-granted` (a forged query/render without the host's grant) `unsupported-route` (1.29.0: a kind outside the binding's optional `routes`, checked before the grant) and everything after `dispose`. Every refusal keeps the exact input it was given (`retained`, never parsed, stripped or mutated); `retainedReturnFile(verdict)` turns a retained, intent-shaped input back into a return file, so the person can keep it for another host. The VS Code host binds `routes` to selection, navigate, query and render and leaves `source` returns unrouted: source requests arrive through the viewer's own source message and are never opened automatically. **Download return file** saves the same intent as JSON (`returnFileText`); `parseReturnFile` reads one back for the same guard: the file fallback when no live channel exists. Nothing is transmitted, applied or stored by these functions.

The independent consumer adds a third viewer with a session host: grants, revision advance, dispose and reopen (a new session ID), replay and a return-file loader. The browser test covers read-only default, refused apply/publish, query and render payloads, the file accepted once then replayed, a stale file after a revision change, a disposed session and a reopened session refusing the old file.

## Standalone VS Code / Cursor viewer (source package)

`hosts/vscode` is its own extension manifest (`diagramcloud-viewer`, engine ^1.90.0, commands `diagramcloud.viewer.open` and `diagramcloud.viewer.loadReturnFile`, setting `diagramcloud.viewer.grants`, default `[]`). The extension validates the chosen file, sends the webview only `publicDocument` of it, and routes every message through `hosts/vscode/src/hostCore.ts`: card selection is host-controlled (exact project and revision), returns go through the guard, query/render payloads open as untitled unsaved documents, source requests are logged and never opened. Closing the panel disposes the session; opening again creates a new one. The webview policy is one nonce script, local style, `connect-src 'none'`, no fonts or frames.

Build: `npx tsx scripts/package-vsix.ts [--out <new directory>]` (default `.local/vsix/<commit>`). It type-checks the host (`hosts/vscode/tsconfig.json`), bundles with esbuild (no source maps, generic icons only), collects the licenses of the bundled packages, writes the `.vsix` (Open Packaging ZIP) and reads it back with `src/core/interchange/zip.ts`, then writes `vsix-receipt.json` (members, hash, source commit). `tests/react-viewer-vsix.test.ts` checks the member list, manifest, policy and absence of local paths; the browser test loads the packaged webview bundle under its real policy with a simulated extension host built on the same host core. **Installed-host proof (VS Code, local only):** `npm run test:host:vscode` (`tests/host/vscode-host.test.ts`) builds the VSIX, downloads VS Code with `@vscode/test-electron` (cached in `.local/vscode-host/vscode-test`; `DIAGRAMCLOUD_VSCODE_VERSION` picks a version, `DIAGRAMCLOUD_VSCODE_EXECUTABLE` uses an existing Code executable), installs the `.vsix` with VS Code's own CLI into an isolated `--extensions-dir`/`--user-data-dir` under `.local/vscode-host/<run>` (never the person's profile, no inherited `VSCODE_*`/`ELECTRON_*` variables), and drives the workbench and the webview with Playwright's Electron driver on a synthetic document: activation by command, read-only default negotiation (only *Return selected context* enabled, no private sentinel in the webview), host-guarded card selection, live selection return, a return file accepted once then refused as replayed, a stale revision refused, closing the panel (later return refused as closed), reopening as a new session (the earlier session's file refused as another session, a new live return accepted), explicit grants `render`+`apply` (render granted and its SVG opened untitled, apply listed as refused), then uninstall. Outcomes are read from the extension's own output-channel log; a receipt (`diagramcloud.vscode-host-proof/1`, VS Code version, VSIX hash, each step's log lines) is written to `.local/vscode-host/<run>/receipt.json`. It needs a desktop session and a ~335 MB download, so it is not part of `npm test` or CI. First pass (17 Oct 2026): VS Code 1.142.0 win32-x64, all five journey subtests passed. **Not claimed:** Cursor, update/rollback of the extension, Marketplace publication or signing, and the *Download return file* button inside the webview (the return files are written by the test).

## Label focus stability (react-viewer flake)

CI run 38983241191 failed at "Clone internal document" then Enter on a focused label: the selection stayed on the earlier edge. Cause: Canvas dropped every card measurement when the document object changed, even for an equal-content clone; React Flow then reset handle bounds and unmounted every connection and its label until the cards were measured again, so the focused label was detached between focus and key press (a MutationObserver recorded both labels removed on every local run; slower CI hosts lost the key). Canvas now keeps the measurement of a card whose drawn content is unchanged within the same view and capability scope, and SceneEdge keeps one stable label `<button>` for its life, exposing `data-placement` (`placed`, `hidden`, `pending`) instead of swapping to a `<span>`. The canvas frame exposes `data-label-placement="settled"` once every card is measured. The test waits for that signal and asserts with a MutationObserver that no label button is removed across the clone, the 390 px resize and the key presses; exactly-once delivery and no host-form submission are unchanged.
