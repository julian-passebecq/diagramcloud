# Private supplied usage files

Workflow → Supplied usage and cost can read an explicitly selected JSON file into a separate review. **Use these records** replaces only the session form, clears its old calculation and focuses Calculate. **Keep current inputs** preserves the form/result and returns focus to the file picker. Invalid files never change current inputs/results. Editing, clearing, calculating, selecting a newer file or unmounting invalidates pending reads and reviews. The existing author-only project/revision-keyed host removes this panel on project/revision/public changes; a late read cannot return into the new session.

The thin transport is `{ "format": "diagramcloud.supplied-usage", "version": 1, "visibility": "private", "draft": ... }`. The draft is the existing `UsageDraft` shape, except local React `key` fields are omitted from records and allocations. No Project ID, scope binding, totals, derived result or authority grant is transported. This is a portable private supplied-input file, not a Project document or collector/billing interchange standard. Every supplied call is declared to belong to the one UTC window; membership and citations are not independently certified.

All existing draft field names and numeric strings are retained exactly: `basis`, `windowStart`, `windowEnd`, `featureFilter`, and `records`; each row has `authority`, `id`, `source`, `inputTokens`, `outputTokens`, `cachedInputTokens`, `reasoningOutputTokens`, `amount`, `currency`, `costBasis`, `costSource`, `allocations`; each allocation has `featureId`, `basisPoints`. Blank counts/cost remain unknown and explicit `"0"` remains supplied zero. Local keys are regenerated uniquely, and subsequent new rows/allocations start after the highest imported key.

Fields are exact and version/private scope explicit. Unknown/missing fields, duplicate decoded JSON keys (including escaped aliases), invalid UTF-8/BOM, incomplete input, conflicting call identities/provenance and unsupported versions are refused whole. Identical readbacks retain the arithmetic engine's existing deduplication. The envelope and selected file are capped at 256 KiB UTF-8; up to 50 rows and 10 allocations per row. The existing `calculateUsageDraft` remains semantic authority, including UTC bounds, explicit currency/basis/citation, numeric limits, subsets and exact-remainder underflow refusal. Shared `usageEconomics` arithmetic is unchanged.

**Download validated usage inputs** validates the current form through the same parser, then downloads only inputs, not results. An invalid form/download failure preserves the current session state. Files are private, unencrypted and user-selected; downloading is not Project save, persistence confirmation, public sharing, provider verification or a bill. No rates, provider calls, forecasts or remote writes are added.

Qualification: `tests/usage-economics-files.test.ts` covers strict shape, string preservation, duplicate keys/identities, byte/row/allocation limits and read errors. `tests/e2e/usage-economics-files.spec.ts` exercises the full App at 1440 and 390 pixels: review/cancel/use/download, input/result preservation, fresh keys, no Project/Undo/storage mutation, late read/edit/new-file/clear/public/project/revision guards, and focus restoration. Existing usage tests remain part of focused validation.
