# Canonical connection table in Relationships

This proposed local slice completes the existing **Relationships** sheet rather than adding another explorer. It reads the same validated Project as the canvas. It does not change Project, views, positions, typed relation schemas, storage, observations or source collectors. A prepared patch and parser result are not qualification.

`relationshipTableFacts(project, {publicMode, repositoryId?})` is a pure presentation projection. It first uses the existing permitted overview/public projection, then `repositoryOutputFacts`. Omitted repository selection means current Project; an explicitly supplied empty, unknown or unavailable repository returns an empty unavailable scope with no global fallback. Existing repository namespace/endpoint rules are reused, not upgraded into many-to-many membership or inferred ownership. No private acquisition or graph-history receipt is needed by this branch.

Each canonical connection appears exactly once in source order, identified by its stable edge ID, with exact from/to IDs and labels, native kind, supplied label and basis. Missing basis is explicitly not supplied/UNKNOWN; explicit `unknown`, `planned` and `static-source` remain distinct. Repeated memberships in multiple permitted views are listed without duplicating the connection. Authoring connections without any permitted view membership remain visible as not placed; publicDocument retains only its permitted reachable view closure. Membership labels and IDs are exact canonical references, never name-based joins.

An optional quantity retains value, unit, provenance and note unchanged. Zero is a valid displayed value. A synthetic amount remains synthetic, and a missing amount stays UNKNOWN rather than becoming zero. The illustrative speed field is deliberately not rendered: it is neither timing nor an asynchronous-delivery guarantee. No quantity is computed or inferred.

**Endpoint source context** lists only exact sources cited by the two endpoint nodes after privacy filtering. It is explicitly context, not independent evidence for the connection. ProjectEdge has no direct sourceIds, assertion, confidence, cardinality or asynchronous-delivery contract; these remain UNKNOWN. The table does not parse labels, source locations or a filename suffix to invent them, and does not join experience relations, GraphSnapshot assertions or a transient AnalysisBundle by ID, label or proximity. Sources use inert text, not new path, network or source-opening capabilities. Richer native relationships and inspectable producer losses remain a separate open contract.

The table displays at most50 rows at once, with native Previous/Next controls, accessible caption/column headers and a labelled keyboard-focusable horizontal scroll region. Status gives the total permitted distinct connections, current row range, rows after that page and page count. Every permitted row remains reachable. Totals describe only the supplied filtered document scope, not complete discovery upstream. Counts are computed after public filtering; no hidden-name list, original-minus-public count or private omission count is exposed. All existing relationship-view buttons keep their existing callback and are now listed instead of silently truncating after seven.

Rows are inert and cannot select, navigate, mutate or propose a patch. Paging or expanding endpoint context keeps the active selection, current parent path, revision and Pin untouched. Existing view buttons are explicit navigation actions: App.goToView(viewId) ordinarily clears selection unless a nodeId is supplied. This slice does not change that callback, introduce a route, or claim that activating it preserves selection. Existing parent-path navigation and Pin resolution continue to govern the result.

Paging is temporary state scoped by Project ID, revision, public/author exposure and explicit repository selector. Changing those inputs remounts only the table's internal paging component, before old rows can render; it never remounts ProjectContext, Navigator or the canvas. Within a mounted table, page is also clamped against actual permitted length. No page, source, selection or Pin data is saved. Public/author transitions recompute fresh facts; a public projection cannot revive a prior private source or membership. Existing Structure/Evidence output and source bridge summaries are preserved.

Existing complementary surfaces remain useful: ProjectContext selected-context download already includes supplied incident edges; the Inspector lists component connections; ProjectNavigator handles hierarchies and explicit mappings; GraphExplorer pages private imported components and traverses its supplied evidence chain; IntelligenceInsights has bounded impact reachability. The public Technical Manual already renders complete per-view connection tables. None is replaced by this interactive Project table, and no export renderer changes.

Original acceptance anchors are `v2:navigation`, `r2:semantic-zoom`, `v2:typed-relations`, `v2:accessibility`, UX `dense`, `compact-full`, `keyboard`, `core-parity`, `relationship-meaning` and `ux-semantic-zoom`. Their exact rows, inherited IDs, blank canonical IDs, hashes and PENDING qualifiers are preserved in the ignored research/proposal. This completes only a bounded local table portion. Semantic zoom is not graphical magnification; macro→field→code host transport, richer relation meaning, semantic saved views, installed hosts and all eight workstreams remain PARTIAL/open. Evidence and proposed contracts are never permission to access, install or publish another product.

Meaningful qualification remains required after reviewed application: preserve existing tests; exercise actual ordinary reviewed import without graph/AI/services, more than50 connections and more than7 views, shared/unplaced membership, exact zero/provenance and missing values, no canonical mutation, scoped invalid repository without fallback, public noninterference, caller-copy isolation, retained parent/Pin, changed scope page reset, keyboard/native controls and390px local scrolling without tiny text or document overflow. No timeouts, privacy checks or import guards are relaxed. Root records actual TypeScript/unit/build/browser and visual outcomes for the final source; no result is inferred from this document.


## Existing component membership and explicit perspective targets (prepared slice)

The proposed Studio Edit command **Reuse existing component** selects an existing stable node ID from the current canonical Project and adds it to an existing displayed view. The command is separate from **+ Component**, which still creates a new component. Duplicate labels are not identities: each native option includes the exact node ID and private visibility when applicable. The chooser uses local draft state, explicit Apply/Cancel, Escape and ordinary keyboard focus. It is not a new document, reference-instance mapping, source association or permission format.

`addExistingComponentToView(project, viewId, nodeId, position)` validates a copy with the existing document/view schemas. Its only change is one absent `view.nodeIds` membership and that member's authored position. An existing membership returns the original object and ignores a replacement position, so the App does not commit, write storage or create Undo for that no-op. Unknown IDs, invalid positions and recursive child expansion are refused with a constant message; there is no fallback view, matching by label or silently removed child link. The helper does not increment revision or save. App's existing ordinary commit performs exactly one validated revision/Undo/save after a changed result.

At Apply, placement is the center of that canvas's current React Flow pan/zoom viewport, converted to existing authored coordinates. A measurable initialized canvas is required; there is no guessed grid fallback, coordinate clipping or hidden relayout. Other positions stay unchanged. This placement does not promise an empty collision-free spot or new fit/readability; ordinary drag, Grid and Auto layout remain separate explicit controls. Existing filters may hide a newly placed member. No source or repository ownership is inferred from its position.

The same canonical component still owns its label, summary, kind, basis, source/evidence references, observations, child view and visibility in every view. Nothing is cloned or relabelled; node/edge/view IDs, all connection memberships, focal hints, story, source revisions, runtime facts and publication flags remain unchanged. A private component remains private and is filtered by publicDocument, even when placed in a public view. Conversely, placing an already-public component in a reachable public view may expose its already-public evidence in public exports: the chooser states this before Apply. Membership itself is authored presentation scope, not observation review, a source grant or cross-project namespace association. View-only removal is deliberately outside this first command; global Delete component retains its existing global meaning.

The optional Canvas callback is supplied only by Studio Edit. Strict controlled selection and the standalone public React viewer never receive authoring from this slice. App reuses the existing live authoring epoch: exact current Project object/ID/revision, displayed view with an actual reachable root path, Edit, diagram sheet, non-Design and no active modal are required. Project replacement, any committed edit/Undo/Redo, mode/public/navigation/modal context changes mask and discard old drafts before they can return. Parent-retaining node drilldown and intentional descendant truncation are unchanged. Apply does not select a new node, switch modes, move Pin, change source scope or save browser panel preferences.

Perspective navigation continues to derive targets from `perspectivesFor` on the caller's already-permitted document. A single reachable supplied target keeps its existing fast button. Multiple targets expose a native disclosure with each exact title and stable view ID; no first target is silently chosen. `pathTo` must return an actual root path, so orphan/unreachable candidates are unavailable rather than using pathToView's fallback. Missing targets stay UNKNOWN/unsupported. No new view, perspective tag or node membership is generated by navigation. A direct target keeps component selection through the existing guarded goToView callback; an explicitly labelled partial related view may not contain that component and retains the existing selection-clearing behavior. Parent chain, Back/Forward and independent context Pin continue to govern return. A changed document/node/callback or unmounted strip revokes earlier target callbacks.

The prepared tests retain all existing bodies/assertions/limits, add pure existing-producer cases for unchanged facts, no-op identity, cycle/position/refusal, public privacy and exact multi-view projection, and add ordinary reviewed-import UI journeys for Cancel, one Undo/save/reopen/backup, private placement, stale context/replacement, target choice, retained parents/Pin and native390px controls. No test, TypeScript, build, browser, fixture or visual outcome is claimed by preparation. Exact-source qualification and root inspection remain required after authorized adoption.

Acceptance anchors are bounded portions of original `v2:shared-root`, `v2:client-authoring`, `v2:navigation`, `v2:accessibility` and `r2:semantic-zoom`, with full original feature/UX rows retained in the ignored plan. All eight workstreams remain PARTIAL. No proposed contract supplies an external grant. ## Proposed scoped removal of an existing membership

`removeComponentFromView(project, viewId, nodeId)` is the conservative inverse of explicit placement. It removes exactly one node membership, that view's position for the node, and incident connection memberships from that same view. Canonical nodes/edges, all other views, story, evidence, sources, quantities, visibility and observations remain unchanged. Global **Delete component** keeps its existing global meaning. The earlier placement-only limit describes the first add command, not permission to call global deletion for unplacement.

An absent membership in a valid explicit scope is an exact identity no-op; unknown/invalid scope refuses with a constant message. Existing `validateDocument` remains the final gate. Authored story node/highlight/observation references and `view.design.focal` are refused rather than rewritten. A temporary root-reachability set follows existing canonical child links once per view; removal that newly makes a child view unreachable in either the authoring or public projection is refused. The public check reuses canonical publicDocument(before/after) view IDs: a private alternate parent cannot authorize losing a previously reachable public child view. Ordinary public component/evidence omission without child-view loss remains an explicitly reviewed membership effect. App also refuses breaking the exact currently retained parent chain even if a different root route exists. It never deletes a child link or picks a replacement parent.

Edit-only **Remove from this view** opens a stable-ID chooser, followed by an explicit impact review listing the target view/component and incident connection memberships. It explains that public output follows reachable public content and can omit unplaced public evidence while authoring facts remain intact. Apply revalidates the live Project object/ID/revision/epoch, displayed reachable view, diagram/Edit/non-Design/no-modal boundary, dependencies and exact retained path. Cancel/Escape, mode/project/import/Undo/context changes revoke the draft. No source association, observation review/shareability, new schema/store/engine or read-only SDK authoring capability is created.

A changed result uses one existing validated commit/Undo/save. Pin and session Back/Forward keep their existing current-projection refusal behavior; no stale facts, retargeted history or automatic replacement selection is supplied. Private visibility is unchanged. Bigger touch targets, automatic fit, arbitrary branch unplacement, durable semantic saved contexts, source-vector adoption and installed-host parity remain open.
