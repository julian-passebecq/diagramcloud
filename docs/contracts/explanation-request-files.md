# Explanation request files in the author form

**Edit → Tours → Author explanation → Load request JSON** reads the existing `diagramcloud.explanation-walkthrough` version 1 request, the same input contract as `npm run explain`. File exchange adds no Project schema, execution format or provider call. Optional browser draft recovery is a separate explicit opt-in described in [Private draft recovery](explanation-draft-recovery.md). A valid import replaces the form's session draft only. Review still prepares the ordinary revision-guarded patch; Apply remains the existing explicit, undoable Project operation.

Every request field is represented and retained: request/step IDs, title and focus question, top-level and per-step citations, view/components/connections, narration and provenance, selected case, earlier-step prerequisites, before/after state, exact code-block line range, takeaway and questions. Step identities appear in legends; adding steps cannot reuse an unresolved prerequisite identity. Unknown fields or versions are refused rather than dropped. The existing compiler normalizes whitespace when decoding; source project ID, revision and fingerprint are never replaced.

The loader accepts at most 4 MiB of UTF-8, checks the file size before reading and the returned byte count after reading, refuses invalid UTF-8, and validates the strict request schema. It checks exact references against the open Project: source citations, view membership, attached code/ranges, unique IDs/state fields and earlier prerequisites. Missing subjects, unsupported fields and malformed/unreadable files leave the previous draft and its basis untouched. Changing the Project or editing the draft during an asynchronous read refuses the pending replacement. Closing the form invalidates that pending read.

A request for another project is refused. A same-project request whose revision or fingerprint differs can load if its references remain resolvable. It is explicitly stale, retains the supplied basis, and disables Review. The file does not contain the historical Project; current matching IDs do not prove historical source content. To review, load it again after opening its exact original source. The form does not refresh the fingerprint, infer equivalent IDs, reconstruct old source or automatically adopt newly available source choices. A stale file with references missing from the current project is refused because those references cannot be represented/validated in this form.

Two explicit export actions have different purposes:

- **Download validated request file** checks the request schema and references first. Its JSON can round-trip through this loader; an original stale basis stays stale. Validation or size errors stay visible and preserve the form.
- **Download request draft** and **Download draft before closing** preserve incomplete or stale authored fields for recovery. These downloads retain the previous plain request-shaped JSON behavior, not a new draft format. Incomplete JSON must be completed before this strict loader can import it; the UI says so. A download is not a Project save or an execution receipt.

Files remain private author inputs/outputs. File import itself does not enable autosave; the separate private draft recovery control can persist an incomplete form locally after explicit opt-in. All actual authoring still passes through the existing source fingerprint, review, native patch and history guards; public projection remains unchanged by private explanation content.

Implementation: `src/intelligence/explanationRequestFiles.ts` and `src/ui/ExplanationRequestDialog.tsx`. Source tests cover schema/field round-trip, stale binding, ref rejection, byte bounds, UTF-8 and read failure. `tests/e2e/explanation-request-files.spec.ts` exercises 1440/390 form import, all structured fields, both download paths, Back from review, Apply, unchanged public content, stale inputs and refusal without draft/Project loss. The established explanation-request journeys remain regression coverage for incomplete recovery and source-drift behavior.
