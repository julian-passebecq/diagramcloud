## Direct repairs and boundaries

1. Saves are serialized as before, but pending failure is tracked per project. Saving B cannot erase failed A.
   A successful newer A save can resolve A. Legacy single-document queue callers retain their API and semantics.
2. A failed IndexedDB-open attempt is cleared only if it is still the cached attempt. Synchronous denial no longer
   permanently poisons the promise. Blocked late successes are closed, not adopted. No policy is bypassed.
3. Startup drafts are compared to stored content, not merely revision numbers. Different content with the same
   revision is a conflict. The stored copy stays untouched; subsequent edits of the unresolved draft stay in memory.
   Exact-equal content need not be rewritten. New unrelated projects remain saveable.
4. The actual App exposes backups for every named pending in-memory draft, not just the current project.
   Downloading a backup does not claim the database save succeeded or clear the pending guard. Public presentation
   receives a generic warning with no private identities/error details or full authoring-backup controls.
5. Interview Clear/Keep/Confirm restores keyboard focus to an existing control. Explicit topic/question navigation
   focuses the question; passive mounting or a changed source does not steal focus from the host.
6. Multi-project backup controls wrap within a compact viewport using the existing app stylesheet. The old flexible
   alert layout produced 404px document width in a 390px controlled native-style fixture; corrected width is 390px.

Remaining limitation: startup-conflict resolution is deliberate backup -> reload -> review, not an automatic merge.
No cloud sync, storage permission change, data migration, scoring, execution or new canonical project schema is added.
No global privacy audit or universal loss-proof claim is implied by the focused recovery fixes.
