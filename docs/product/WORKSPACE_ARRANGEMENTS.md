# Named workspace arrangements

The V3 workspace's **Layout → Saved arrangements** saves physical reading arrangements in this browser. Supply a name, choose **Save arrangement**, then select a saved name and **Restore arrangement** when wanted. **Delete arrangement** removes that saved entry without changing the current arrangement. Opening/reloading a project does not automatically restore a preference. Duplicate names are refused; choose another name or explicitly delete the old one first.

The arrangement contains the existing WorkbenchLayout only: Explain/Compare/Present-focus preset, explorer side, requested explorer/companion widths, comparison split, bottom height, explorer/companion/bottom collapse, compact active pane, route-bar collapse, route-map collapse and optional companion/bottom floating rectangles. Present-focus is physical layout, not Present mode or permission. Resizing/clamping for the available viewport does not replace requested dimensions.

Drag the separators beside Explorer and Companion or above the bottom panel. Focus a separator for arrow-key resizing (Home/End reach its bounds); Escape during a drag cancels that drag. The labelled range controls remain available in Layout, including on compact screens. Compare's companion separator adjusts its percentage; Explain's adjusts pixels. Explorer side can move the explorer to the right. The companion and bottom panel also offer **Float / Dock** on desktop. Floating moves the same mounted content inside the workspace: no new window, document, tab reset or graph camera change. Use **Move** or **Resize ↘** as pointer handles or focus either and use arrow keys (10 pixels; Shift for 1 pixel). Home/End use the available bounds; Escape cancels a pointer drag. The Float/Dock button retains focus across placement changes. Floating rectangles fit below the workspace header and above its status bar, and a focused float is raised above the other float. Compact screens temporarily use the existing one-pane navigation; Present focus hides the floats, preserving their requested placements for return. The labelled ranges still adjust the docked desktop sizes. This supports these two placements only, not a general drag-docking tree, browser windows, arbitrary pane nesting or floating the Explorer.

Storage uses `diagramcloud.workspace-arrangements.v1` with exact host, project ID and author/public audience scope. The UI is keyed by that scope, so author names/drafts/notices cannot remain in the public arrangement picker or another project's picker. Records repeat and validate their scope; copying a foreign envelope into another key is refused. Names are at most 60 characters; at most 12 arrangements and 32 KiB of UTF-8 are permitted per scope. No project title matching, graph identities, selected component, source, camera, route, document revision or Undo entry is stored or applied. These preferences do not grant host access or authorize publication. Origin storage is not encrypted or synchronized across devices.

Older version-1 layouts without `floating` normalize to both panes docked, in memory only. New layouts store `floating: {companion, dock}` with null (docked) or exact integer `{x,y,width,height}` rectangles; malformed/extra/nonfinite/out-of-range fields refuse the whole record. Coordinates are bounded to 0–8192 and requested sizes to 120–2000 pixels; effective minimum sizes are 260×180 for companion and 320×180 for bottom, clamped to the measured space without silently rewriting the saved request. Restore remains explicit after reload.

Reads do not repair or overwrite invalid/future records. The UI reports corruption, preserves the raw record, and offers **Discard invalid arrangement data** as an explicit operation before saving again. Blocked/full storage reports failure and keeps session manipulation available. Restore, save and delete re-read and compare the exact observed storage string before acting; a changed list is refused until **Refresh arrangements**. This catches stale selections/observed foreign changes, but localStorage has no transactional compare-and-swap across tabs. It is a UI preference store, not the Project's IndexedDB conflict protocol.

Implementation: `src/core/workbenchLayout.ts`, `src/core/workspaceArrangements.ts`, `src/ui/WorkspaceArrangements.tsx`, `src/ui/WorkbenchFrame.tsx`. The App supplies only the current exact project/audience/host scope and retains the one layout state. Existing classic Studio and linked-view preference records are unchanged.
