# Full-product candidate interfaces and limits

This is implementation documentation for the unmerged candidate; `docs/ROADMAP.md` owns future work. It continues PR #57 and Project schema 1 without a second graph store, service or required model. `outcome.json` records original F feature acceptance separately from bounded additions.

## Working browser journeys

New analysis → Graph → selected JSON → validate/private preview → apply → Business overview. Filter imported organization/project/family/declared state/origin/search; open supplied evidence chain and exact inert source locators; choose one of seven views. Parent navigation uses explicit `parent_id`, existing canvas/back/minimap and parent-retaining child views. The navigator gives separate keyboard targets for selecting a parent and collapsing its children. A 10,000-node schema maximum is not a canvas promise: the selected file is limited to 4 MiB; beyond Project budgets, a paged table lets the person select at most 450 nodes. The resulting scope is partial and drops no existing work. Changing source text clears that transient selection.

Reimport matches graph identity and stable external IDs; same generation with different contents and conflicting semantic identities are refused. It retains authored captions, positions, evidence metadata and visibility. Import-owned private assertion evidence refreshes only if unchanged. Source locators include independent repository revisions. Last three generation receipts are chunked private evidence blocks; forced publication still strips them. Missing items remain uncertainty; only complete, comparable, exact-predecessor tombstones produce a separate reviewable assertion-removal patch. The person chooses whether to apply it. Source counts, scope and history do not reach public exports.

Edit → Business overview → Environments and delivery → select existing component, environment name and optional artifact version → review patch. `diagramcloud.delivery-brief/1` can also be loaded through JSON / AI or CLI. Additive `Project.delivery` contains environments, artifacts (optional declared digest), distinct instance nodes and promotion gates with optional existing observation references. It never makes observations. Declarations start private; stable instance identity cannot switch component or environment. The matrix uses reviewed external observations on the **instance node**, never a logical-component claim. Only observed/verified claims with a declared revision produce same-revision/revision-difference; all other comparisons are UNKNOWN. Neither result proves health, causal drift or a deployment rollout.

Edit → Project Evolution → choose previous authoring JSON (12 MiB maximum). It validates project identity and source/parser/profile/repository membership; shows comparable/partial/incomparable, source-qualified meaning/evidence/claims, connection changes, authored position changes and not-in-scope facts. Open current component navigates the existing Project; the selected backup stays transient. Graph imports additionally expose their retained generation timeline and comparison. This is not repository history, a migration planner or a causal timeline.

The workbench ranks seven recipes by explicit facts and purpose, explains availability, previews 24/60 components according to depth, and opens existing views. Depth also bounds impact traversal; direction and include-unknown basis change supplied-edge reachability. Missing reviewed checks are evidence gaps, never test-coverage percentages. Knowledge shows only admitted Markdown/CSV headings/records and explicit links. Gallery projects and Atlas repositories keep separate revisions; `projectCollection` is currently a pure summary helper, not a new collection UI.

## Static analyzer support

| Selected format | Implemented source facts | Explicit limits |
|---|---|---|
| dbt manifest v4–v12 | model/source/test/seed/snapshot/exposure unique IDs and `depends_on.nodes` | No SQL, macro execution or generated runtime result; newer versions refused with diagnostic |
| Databricks bundle YAML/JSON, resources YAML, `*.job.json` | jobs/tasks and exact `depends_on` declarations | Selected files only; no filesystem/glob fetching, target substitution, workspace/deploy execution |
| PBIR/PBIP major 1–4, selected TMDL/pbism directory | report/model, table/measure/relationship declarations; exact report datasetReference and supported relationship endpoints | No DAX/evaluation, tenant API, full PBIP semantic resolver or type-system claim |
| `.sln` / `.slnx` / `.csproj` | exact selected solution/project references, declared NuGet versions | No build/MSBuild evaluation, implicit source server join, ASP.NET route/EF/deep call graph |
| Swagger 2.0 / OpenAPI 3.0–3.1 JSON/YAML | supplied routes/verbs/schemas, exact local schema `$ref` | No fetch of external schemas or implementation inference |
| Bicep | resource symbol/type/API-version declarations | No ARM/azd resolver, template evaluation, resource health or complete dependency graph |

Domain adapter version is `diagramcloud-domain/2`; facts link file:line, cited source and related declaration. Its source content identity is explicitly a non-cryptographic reproducibility fingerprint; acquisition retains its separate SHA-256 digest. Direct inputs omit sensitive/unsafe/oversized files with a count diagnostic; duplicate paths are refused. Budgets: 1,500 files, 512 KiB per file, 145 facts, 220 links, 80 diagnostics; CLI JSON input maximum 12 MiB. Existing Quick/Standard acquisition has its own tighter budgets and omission inventory. DiagramCloud never verifies a producer's source SHA by fetching its locator.

## Export and automation boundaries

`intelligenceReportHtml` is a semantic static public report: contribution/scope, authored story, component basis/status, environment/artifact/instance claims, promotion gates, verification, public sources and gaps. It uses `publicDocument` before rendering, escaped text and offline CSP. Existing Technical Manual, figure book, Classic/Editorial/Blueprint, Diagram Design, SVG/PNG/HTML/PDF, editable and picture PPTX, AtlasNote, draw.io and Mosaic adapters remain their existing paths. The Deployment figure now uses declared environment memberships when present, retaining generic provider zones otherwise. Generic registry entries reuse original kind glyphs and record MIT origin; no vendor artwork or fonts were altered or added.

Optional `npm run intelligence:mcp -- <selected-document.json>` implements newline-delimited JSON-RPC stdio, [MCP 2025-06-18 transport](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports) and [tools](https://modelcontextprotocol.io/specification/2025-06-18/server/tools). Tools: `diagramcloud_query`, `diagramcloud_render`, `diagramcloud_propose_design`, `diagramcloud_verification_spec`. Initialize then `notifications/initialized`; requests/output are bounded at 1 MiB. Public queries cannot expose private counts, nodes, evidence or sources. Verification proposals are NOT_RUN. No arbitrary path argument, network listener, model, mutation tool, collector, execution or settings change. This selected-file client is not claimed to implement every MCP transport or optional protocol capability.

Project schema 1 accepts optional `delivery`; older documents need no migration. Older clients may drop unknown additive fields on resave: use this candidate and retain full authoring JSON when editing delivery. CLI modes create a new directory and never apply their proposed document. DataPass sidecar and existing Lens pointers remain optional; no cross-repository contract changes. A real private Brain snapshot has not been supplied, so its installed integration acceptance remains pending.
