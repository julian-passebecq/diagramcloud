## Author a request in the App (source candidate)

Choose **Edit → Tours → Author explanation**, select exact existing subjects and citations, and write the question, ordered steps and narration. Optional fields add before/after state, a frozen code excerpt and takeaway. **Review explanation** calls the same compiler and shows the proposed private changes without editing the project. **Apply explanation** uses the ordinary patch validator as one revision and one Undo. **Back to request** keeps all authored fields and the original full source basis; source drift, including a change at the same revision, is refused rather than silently adopted. A missing Tours collection requires **Initialize Tours for explanations** as a separate explicit, undoable edit before drafting.

The private draft is session-only; request and proposed-patch downloads are files for the author, not project saves or persistence receipts. The form has no request-file import, draft autosave or AI execution, and does not expose every CLI prerequisite, case or question input. Code and state remain authored, frozen or synthetic content, never an executed trace. Companion Contract and Questions tabs remain open UX31-related limits.

Implementation: `src/intelligence/explanationRequestDraft.ts`, `src/ui/ExplanationRequestDialog.tsx`, `src/ui/ExplanationAuthoring.tsx`. Coverage is defined in `tests/explanation-request-draft.test.ts` and `tests/e2e/explanation-request.spec.ts`, including "Back to request retains every authored field and original source basis before review and Apply" at 1440 and 390 px. These test definitions do not replace the actual combined-source results recorded in the integration pull request.

## Five meanings kept apart

1. **Structural relation**: A depends on B; a field maps to another field.
2. **Behavioural occurrence**: attempt 2 calls the same endpoint again; a guard selects one case; an acknowledgement or a compensation is its own event.
3. **State and constraint**: before/after values, permitted transitions, invariants, grain, types, permission boundaries.
4. **Evidence**: a source declaration, an authored illustration, an observed run, a measured sample and an inferred candidate each keep their own provenance and uncertainty.
5. **Presentation**: chapter, frame, camera and narrated order explain; they never establish execution, causal order, elapsed time or authorization.

A full interaction model would need occurrence IDs separate from participant IDs, explicit send/receive and correlation, alternatives, loops, parallel regions and a known partial order. The walkthrough compiler does not pretend this exists: it builds authored snapshots over the existing actors and connections, so a retry or failure case can be explained now without a simulator. Formal UML/BPMN, code execution, general trace import and model checking are out of scope.

## UI direction (companion pane in the V3 workspace since #109; Contract and Questions tabs not built)

Explain the selected subject in the main pane; a companion offers Explanation, Code/State, Contract, Related concepts, Evidence or Questions only when useful. Follow and Pin stay explicit and go through the existing context dispatcher. A related-context graph uses the same identities, never label matching; project-wide expansion is asked for, not automatic; cycles and multiple parents stay visible and a list is always an acceptable alternative. Returning from a detour restores source, question, view and step, but never revoked access. The bottom dock keeps its customizable policy. Lessons offer manual stepping, full text alternatives and no forced motion; no TTS, video, whiteboard database or collaboration backend is a prerequisite. The focused HTML export improves current-view and code reading; it is not the V3 mobile shell.

## Optional renderers: ConceptMotion and VizForge

Both are optional adapter candidates for a concrete need, never release dependencies or default runtime. ConceptMotion (teaching, algorithm and data-platform scenes with a controlled player) suits queue, heap and loop state; VizForge (a D3 analytical engine with scene and story validation) suits time series, rankings, distributions, flows and comparable cost/quality stories. If one is selected: permitted data, then payload-specific validation, then one frame index and reduced-motion state owned by DiagramCloud or the host (never two players' clocks at once), then the renderer, then explicit subject selection and export. Test missing renderer, invalid payload, stale source, unmount cleanup, reduced motion, fallback text and export. Donor notices are kept and redistribution scope is settled before any donor byte ships; no donor code is copied here. T3 stays optional.

## Tour staleness (UX34, implemented in #105)

A stop records `referencedFingerprint` over the reference closure of its subjects (evidence blocks, cited sources, image assets) in `src/core/tours.ts`, so changing referenced code, a table or a source makes the stop stale. Legacy stops keep their old comparison and are never re-recorded silently; `publicTours` recomputes it on the public document, so no private content is hashed into a public identity. Proof: `tests/tour-referenced-content.test.ts`.

## Coverage review (27 domains)

Coverage levels: **native** (existing source handles it within stated bounds), **authored** (expressible with explicit authored content, with the gap named), **new** (this complement), **prior** (V3 patches A-D), **optional** (an adapter not adopted). No overall coverage percentage is implied. Any domain with gaps can still be explained by authored content with a text or table fallback.

How to use it: choose the question, source and audience first, then the representation, and name what its inputs cannot establish. A readable contract table beats an unreadable graph; an unsupported payload gets a text, table or source alternative, never a fabricated specialised figure. The schema's 24 design choices are not semantic coverage, and the gap checker (`src/intelligence/learning/gaps.ts`) only considers timing, quantities and concept mappings today.
