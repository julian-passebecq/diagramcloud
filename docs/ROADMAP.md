Explicit Float/Dock and pointer/keyboard movement reuse the same mounted panes. Saved arrangements include those physical placements, with old records defaulting to docked; restoration remains explicit and does not rewrite route/camera/source state. A floating Explorer and a comfortable/compact frame density shipped in 1.34.0 (#142, [contract](contracts/workspace-density.md)). Separate browser windows and arbitrary docking trees remain open. Exact-source integration qualification remains separate.

The companion now reads authored Contract and Questions evidence; the request form exposes cases, prerequisites and per-step citations. [Request-file exchange](contracts/explanation-request-files.md) preserves the original source binding and routes complete imports through ordinary review/Apply. Incomplete draft backups remain separate from validated request files. [Private draft recovery](contracts/explanation-draft-recovery.md) is opt-in, browser-local and explicit on reopening; it retains the original source binding and refuses stale review. Storage failure and observed conflicts remain visible. [Private authored answer records](contracts/question-answers.md) now retain exact question/source bindings and explicit named recorded review. Editing an answer clears its review, source drift makes records read-only, and Apply rechecks the patch against live content. Remote execution remains open.

The Workflow dock now has a [compute capacity scenario](product/COMPUTE_CAPACITY.md) surface over the existing arithmetic engine. Supplied usage/window and activity/floor assumptions are explicit and session-only. This does not supply the delivery queue, access, calendar or agent scheduler model. Sources & Git can explicitly inspect a host-allowlisted checkout through the native adapter; supplied repository history remains a separate source and cloud hosts report local checkout inspection unavailable.

[Supplied usage and cost](product/SUPPLIED_USAGE_20261104.md) now exposes the existing leaf-call arithmetic in Workflow, with explicit provenance, one declared UTC window, unknown counts and separate currency/cost-basis totals. No provider rates, bill or token forecast is inferred. [PM task correspondence](contracts/delivery-task-reading.md) supports up to eight exact supplied snapshots in a bounded session inventory, so a plan can reference multiple scopes or revisions without a newest-source fallback. Explicit result references can be opened when they are safe HTTPS URLs. These are reading and calculation surfaces, not PM dispatch or result collection.

A token forecast, queue model or claimed current activity requires an actual model and supplied evidence. Supplied allowances and static snapshots are not measurements, execution or live scheduling. UX29/UX30 remain partial where queue/calendar/actual-result evidence is absent. No live collector or dispatcher is launched by this roadmap.

T3/Mosaic, remote MCP, local-model and selected external-owner integrations retain their own source, capability and acceptance requirements. Missing external authority does not block independent authorized DiagramCloud implementation, but it does prevent claiming that an untested owner integration is complete. Do not rebuild FOIL tools, a portfolio website or another orchestrator as a substitute.
