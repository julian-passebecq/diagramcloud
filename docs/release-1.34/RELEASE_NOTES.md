# DiagramCloud 1.34.0: connected workspace, source refresh and boundary fixes

**Source release only.** This page describes source merged on `main` after 1.33.1. No package, deployment, tag, Marketplace publication or installed-host result is claimed here; the last recorded private package is still `diagramcloud/1.33.1-0892f9d` in `outcome.json` `privatePackages`. Document schema stays 1. No new runtime dependency.

Each PR keeps its own exact-head evidence. Every entry below was confirmed against its merged PR on 5 November 2026; nothing was dropped.

## Merged

- **Whole-project gallery and anonymous retail example (#133).** Foil/cloud, a new anonymous retail Project (23 components, 30 planned relationships, five views, six story steps), the general catalogue and guided project creation are the gallery entry. A trusted DataPass build may open an independent comparison companion in a new tab; standalone builds omit it and no project is transferred. Tests: five browser journeys (drilldown with parent kept, shared-component edit/Undo/reload, invalid import without mutation, Foil/catalogue, offline HTML without private content, mobile keyboard); matcher snapshot digests unchanged. Limits: no client topology, endpoints, measurements or schedules; no execution engine.
- **Observed components in architecture comparisons (#134).** A component that already carries a permitted reviewed observation reads OBSERVATION IN VIEW (including Partial and Not observed) instead of UNKNOWN in the ledger and SVG. Missing, private, unreviewed and scoped-only claims stay UNKNOWN. The comparison never creates or reviews an observation.
- **Connected workspace panes, source-bound answers and workflow reading (#135).** The bottom dock has Project, Workflow, Sources & Git and Reviews panels; tree hover/focus drives the right-pane details; saved arrangements, resizable panes and Float/Dock of the companion and dock. Authored Contract/Questions, cases, prerequisites and citations; request-file exchange and opt-in explanation-draft recovery; private authored answers with a named recorded review through the ordinary JSON preview/Apply (exact question/block/source binding, drift makes them stale); Show workflow steps; supplied usage and capacity arithmetic with strict private usage-file import. Tests: 2,210 unit and 428 browser tests on the exact-source CI run recorded in the PR. Limits: attribution does not authenticate a reviewer or establish truth; no provider rates, bill, token forecast, queue or dispatcher; native checkout inspection is private and allowlisted.
- **Lesson depth scenes as spatial figures (#137).** `depthSceneViewSpec`, `depthHighlight` and `depthFigureDocument` (`src/intelligence/learning/depth.ts`) and `src/ui/LessonDiagramFigure.tsx` draw a lesson depth scene with the shared export scene: frames come from explicit `childViewId` drilldown only, a dependency never becomes a container, a public audience reads `publicDocument`, camera zoom sizes the figure only, reduced motion has no transition. The list stays the text and keyboard alternative. Tests: `tests/learning-depth-playback.test.ts` (5 new); `tests/e2e/learning-depth-playback.spec.ts` at 390 px reduced motion. Limits: a route can cross a frame border; clicking the figure does nothing; authored positions are used as they are. Contract: `docs/contracts/lesson-diagram-figure.md`.
- **Import bounds (#139).** Visio parts inflate at most to their declared size (≤ 64 MiB) and a size mismatch is refused as damaged; draw.io compressed pages share one 12 MiB budget and a PNG zTXt chunk is limited to 12 MiB; a draw.io parent cycle is detached and reported; Mermaid `&` lists drop repeated keys and link expansion stops at 4 × `MAX_EDGES` with the skipped pairs reported. Tests: `tests/import-bounds.test.ts`. Limits closed by #148 (below): the per-view connection cap, the Visio total budget and the App file-size check.
- **Monotonic revisions and polynomial parent paths (#140).** Undo and Redo restore the exact stored document; the history keeps a high-water mark, so the next edit after an Undo gets a fresh revision and a patch written for the undone state is refused as stale. `parentPaths`/`pathToView` deduplicate links and prune branches that cannot reach the target (the 12-path cap and truncation flag are unchanged). Tests: `tests/core.test.ts`, `tests/hierarchy.test.ts`; explanation-request, JSON drawer and navigation-context browser specs. Limit: a reload starts a new history and forgets the high-water mark.
- **Public-boundary fixes (#141).** `validateProposal` refuses a proposal that records or changes a review basis or adds/changes a compatibility record (`self-review`) on manual import, CLI and MCP alike; `diagramcloud_propose_mapping` runs its duplicate check and dry run on `publicDocument`, so a hidden mapping is no longer revealed; JSON Patch `add <member>/-` creates an absent array; a local Galaxy app's `locator` is its Galaxy ID, never its path. Tests: `tests/proposal-parity.test.ts`, `tests/public-noninterference.test.ts`, `tests/atlas.test.ts`, `tests/patch.test.ts`. Limit: compatibility records are compared per `requirementId`.
- **Floating Explorer and compact density (#142).** The Explorer can float and dock like the companion and dock (same mounted region, focus kept, suspended on compact screens, in Present and when collapsed); Layout > Density offers comfortable or compact frame chrome; named arrangements carry both, never applied automatically. Tests: workbench-floating, workbench-layout, workspace-arrangements units; `tests/e2e/workbench-floating.spec.ts`, `tests/e2e/workspace-arrangements.spec.ts`. Limits: no separate windows, docking trees, tabbed pane groups or snapping; density covers frame chrome and tab rows only; a build older than 1.34 reads a 1.34 arrangement as corrupt and leaves it untouched. Contract: `docs/contracts/workspace-density.md`.
- **PPTX drilldown footer link (#146).** The PPTX "Open subdiagram" footer links to the child view's slide when that child view is in the public deck. Doc-reading tests normalise CRLF (`tests/helpers/readText.ts`). Tests: `tests/pptx-drilldown.test.ts`. Limit: not visually inspected in PowerPoint.
- **Source refresh summary and recoverable return context (#147).** `refreshSummary` (`src/intelligence/refresh.ts`) lists new, changed, uncertain (not established by the latest scan, never reported as removed), unavailable sources and retained or dropped authored evidence; the JSON review of every atlas rescan shows it. Apply and Cancel return to the recorded view only when its exact `childViewId` path is still permitted, otherwise the generic `VIEW_ROUTE_UNAVAILABLE` refusal and the root. A re-established component loses its "Not established by latest scan" tag. The legacy folder picker now passes an AbortSignal. Tests: `tests/intelligence-refresh.test.ts`, `tests/scan.test.ts`, `tests/e2e/atlas.spec.ts` at 1440 and 390. Limits: the return context lasts for the session only; the legacy picker has no visible Cancel button. Contract: `docs/contracts/source-refresh.md`.

- **Readiness purpose badge (#136).** `purposeBadge` in `src/intelligence/readiness.ts` and a badge under the purpose select of the JSON / AI readiness panel ("Complete for <purpose>" or "N required gap(s) open"), "Go to gap" buttons and the badge in the readiness JSON download. Tests: `tests/intelligence.test.ts`, `tests/e2e/readiness-badge.spec.ts`. Limit: not in the Project overview or V3 workspace; not a percentage, certificate or review.
- **Companion concepts and detour Return (#138).** A Concepts tab only where a stored mapping exists, a selected question bound by exact text, and Return restoring tab, filters and question, refused with the generic message after a project or audience change or a removed or revoked origin. Tests: `tests/companion-pane.test.ts`, `tests/e2e/v3-companion.spec.ts`. Limits: Portfolio/Present remount the companion and drop an author detour; selected question and detour are session state only; a concept opens its lesson since #150. Contract: `docs/contracts/companion-return.md`.
- **Meeting summary PDF and PPTX (#143).** One shared public model (`meetingSummaryModel`) gives HTML (unchanged), a browser-print PDF on A4 or Letter from a sandboxed frame, and an editable PPTX (`src/export/meetingSummaryPptx.ts`, 120-slide limit, native figures, synthetic labels kept, no private text in any zip part). Tests: `tests/meeting-summary-pptx.test.ts`, `tests/e2e/meeting-summary.spec.ts` (A4 and Letter `page.pdf`, PPTX download at 1440 and 390). Limits: the export-menu label in `src/App.tsx` still reads "Meeting summary (HTML)"; PPTX figure boxes drop drilldown links; only Chromium prints are qualified; no CLI or MCP output; no printed PDF read by a person.
- **Revise and remove applied explanations (#144).** Edit → Tours → Existing explanation offers Revise and Remove; `readExplanationWalkthrough` rebuilds the request at the recorded cut and refuses any hand edit, ambiguous source view or unreadable record; revise and remove are one revision and one Undo each, kept stop IDs and visibility stay, answers on kept steps go stale. Tests: `tests/explanation-revise.test.ts`, `tests/e2e/explanation-revise.spec.ts`. Limits: any edit of generated content after Apply blocks Revise and Remove until undone; a step's source view is inferred only when exactly one view holds its subjects. Contract: `docs/contracts/explanation-revision.md`.
- **XML-safe exports (#145).** XML-forbidden characters (C0 controls, U+FFFE/U+FFFF, unpaired surrogates) become U+FFFD in SVG, draw.io and PPTX parts. Tests: `tests/export-xml-wellformed.test.ts`. Limits: not applied to `projectOverview.ts` HTML or `meetingSummary.ts`.
- **Import hardening follow-ups (#148).** `documentFromGraph` keeps at most 1000 connections per view and reports the rest; Visio parts are read once each and charged against one 64 MiB total, at most 160 foreground pages; the App checks a picked file's size before reading it (12 MiB for JSON, SVG, draw.io XML and Mermaid; 16 MiB for Visio and draw.io PNG) and stages nothing when it is too large; the AI guide documents `add` at `<member>/-`. Tests: `tests/import-hardening.test.ts`, `tests/e2e/interchange.spec.ts`. Limit: CLI and MCP input limits are unchanged.
- **Public omission notice in the meeting summary and linked reading (#149).** `DesignOptions.omissionBase` lets a figure drawn from a public copy read view membership sizes from its authoring document, so the meeting summary (HTML, print PDF and PPTX subtitle) and linked reading print the one uncounted `PUBLIC_OMISSION_NOTICE`. Tests: `tests/public-omission-counts.test.ts` (1 and 5 private items byte-identical), `tests/e2e/meeting-summary.spec.ts`. Limits: the design-profile HTML shows the notice twice on a view page; the PPTX is compared by XML, not inspected in PowerPoint.
- **QA UI polish (#150).** Schema refusals read as one `path: message` line per issue (at most 12 plus a count); explanation-request required fields are marked and a refused Review names each missing field and its section; header actions stay on one row at 1440; the lesson source select wraps at 390; the Project context tabs keep whole words; the App passes `onLesson`, so a related concept opens its catalogue lesson. Tests: `tests/readable-errors.test.ts`, `tests/explanation-request-errors.test.ts`, `tests/e2e/qa-ui-polish.spec.ts`, `tests/e2e/v3-companion.spec.ts`. Limits: the header is asserted at 1440 only; one `v3-companion` line now expects lesson buttons, and the read-only list without a handler is checked on the component.

## Limits kept

- No token forecast, queue, calendar or dispatch model; supplied usage and effort stay arithmetic over supplied inputs.
- Cross-project correspondence in linked views, separate browser windows and free docking trees are not built.
- No tag, public release, private package or deployment is claimed by this page.
