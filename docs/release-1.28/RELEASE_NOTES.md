# DiagramCloud 1.28.0: V2 standalone

A bounded milestone on top of 1.27.1, from the [DiagramCloud standalone V2 mission](https://github.com/julian-passebecq/galaxy-prompt-spec/blob/main/missions/2026-10-17-diagramcloud-standalone-v2.md). It is still **not a complete V2**: each acceptance row it changes, with its test or its gap, is in the [R4 crosswalk](../product/R4_CROSSWALK.md), and the eight workstreams in [V2_WORKSTREAM_STATUS](../product/V2_WORKSTREAM_STATUS.md) stay partial. Document schema stays 1; every model addition is optional, and documents without it validate unchanged.

## What is new

- **Evidence figures** ([#79](https://github.com/julian-passebecq/diagramcloud/pull/79)). A `schedule` evidence block draws a **Gantt** figure on a calendar axis (UTC for timed schedules), with estimates dashed and named and provenance printed. Metrics `measure` readings with baseline and current roles draw a **comparison** figure. Its difference is derived and is never a cause or a saving. It is unavailable, with the reason, on a missing baseline, a zero denominator, or an incompatible unit, scope or window. The **Sankey** never merges flows by label or endpoints. One `measurementId` on two connections of one scope is reported as ambiguous, never counted twice. Studio, SVG, the HTML book, the manual and the PPTX deck show the same availability reasons. The model also gains optional tour stop IDs and choice `reviewBasis`.
- **Saved contexts** ([#78](https://github.com/julian-passebecq/diagramcloud/pull/78)). An author can save a named context: parent path, view, selection, sheet, perspective, snapshot, depth, variant and tour stop, as stable-ID pointers scoped by project, audience and host. Each dimension resolves on its own. A lost one falls back with a generic reason while the others are kept. Public modes never read author contexts. Blocked or corrupt storage stays recoverable. A project opened before the local workspace answers now stays open (the studio flake's root cause), and a JSON draft never lands in another project.
- **Visual variants and a three-axis delta** ([#77](https://github.com/julian-passebecq/diagramcloud/pull/77)). Candidates are drawn with the ordinary editors as operations with `test` preconditions, and raw JSON Patch stays the advanced route. A linked side-by-side comparison pairs objects by exact stable ID and shows a missing counterpart as absent. The delta separates layout, architecture and evidence. A candidate component without an observation is UNKNOWN. An explicit rebase shows conflicts before anything is applied.
- **React consumer host session and VSIX source package** ([#80](https://github.com/julian-passebecq/diagramcloud/pull/80)). `diagramcloud.host-session/1` is read-only by default and grants only query and render. Propose, validate, apply and publish are always refused, with a reason. Return intents carry exact project, revision, audience and session, and stale, replayed, foreign or disposed ones are refused, live or from a JSON file. `npm run package:vsix` builds a VS Code/Cursor source package from `hosts/vscode/`. The donor development-atlas contracts are adopted in `src/development/`. The react-viewer label flake is fixed at its root: cards keep their measurement across equal-content documents, and one stable label button is used.
- **Evidence-aware decisions** ([#82](https://github.com/julian-passebecq/diagramcloud/pull/82)). Choices show assumptions, alternatives and a review state derived from `reviewBasis` against current facts, never stored. Review and accept are explicit human Edit actions. The substitution check is UNKNOWN without compatibility evidence; a matching name, provider or family is not proof. An imported accepted decision is never rewritten silently.
- **Tour Resume and tour editing** ([#83](https://github.com/julian-passebecq/diagramcloud/pull/83)). New stops get content-derived stable IDs. Resume finds a stop by its ID and asks when the stop moved, was removed or is ambiguous; it never rebinds. Narration, re-record (connection subjects included), move and remove are each one revision and one Undo. Saved contexts restore the tour position and the selected variant.
- **Proposal parity and offline qualification** (this integration, from [#81](https://github.com/julian-passebecq/diagramcloud/pull/81)). One validator (`src/core/proposal.ts`) serves manual import, `npm run intelligence -- validate-proposal` and the MCP tool `diagramcloud_validate_proposal`, which now gives 10 public tools, or 11 with `--analysis`. The same payload gives the same reasons through all three. The calling path sets the origin, no proposal arrives reviewed, and a replay is refused, also after Undo. Validation launches no provider. A browser journey runs import, inspect, edit, save, reopen, public export and a lesson with every non-loopback request aborted.

## Limits

- The VSIX is proven as a built source package only. It has not been installed or run in VS Code or Cursor.
- Schedules and measures have no form editor; authors write them as JSON. Gantt durations stop at weeks, days, hours and minutes. Comparable windows only need equal length. Units are never converted.
- Environment is always captured as null in a saved context, because no environment selection exists. The new tour controls were not checked at 390x844 or with reduced motion.
- The substitution check always shows UNKNOWN, because the model stores no compatibility evidence yet. Review-needed names which kinds of fact changed, not the exact fact.
- The variant comparison draws export-scene SVGs, not two live canvases.
- The import dialog reads an unknown payload kind as a whole document, so unsupported-kind parity covers the CLI and MCP only.
- Optional external adapters (T3, remote MCP, local model; R4-W7) are not implemented. Only Chromium is qualified.
