# DiagramCloud 1.35.0: interactive lesson figures, CLI/MCP input limits, wave-4 fixes and post-1.34 polish

**Source release only.** This page describes source merged on `main` after 1.34.0. No package, deployment, tag, Marketplace publication or installed-host result is claimed here; the last recorded private package is still `diagramcloud/1.33.1-0892f9d` in `outcome.json` `privatePackages`. Document schema stays 1 (one optional mapping field added, below). No new runtime dependency.

Each PR keeps its own exact-head evidence. All four lanes prepared for this release merged on 5 November 2026; nothing was dropped. 1.35.0 rather than 1.34.1 because #152 adds a feature.

## Merged

- **#152 — interactive lesson figures** (`04cd247`). Each drawn component of the lesson depth figure (`src/ui/LessonDiagramFigure.tsx`) is a real button over the SVG (accessible name = component label, `aria-pressed`, visible focus ring, scene Tab order); the SVG keeps `role="img"`. One selection is shared by the figure, the list (row "Select … in the figure") and a new "Selected component" panel. "Open inside X" (only for a collapsed component, below Detail) moves one semantic depth deeper through explicit `childViewId` drilldown (two-level bound, no view revisited); "Back to <depth>" returns and reselects, and focus follows. It never changes zoom, environment, perspective, variant, run or audience and creates no revision. Pure module `src/intelligence/learning/figureInteraction.ts`; contract `docs/contracts/lesson-diagram-figure.md`. Tests: `tests/lesson-figure-interaction.test.ts` (6 new), `tests/e2e/lesson-figure-interaction.spec.ts` (1440 pointer and 390x844 keyboard-only). Limits: depth is scene-wide, so Open inside on one container opens every container at that level; no arrow-key navigation between figure buttons; frame headers are not interactive.
- **#153 — CLI and MCP input limits** (`e14a49f`). `src/core/inputLimits.ts` holds every input limit once (12 MiB JSON document, 16 MiB package file, 512 KiB ProjectBrief / design brief, 4 MiB GraphSnapshot and explanation input, 1 MiB MCP request line and packaging evidence, 8 / 32 MiB concept-host viewer / packet, 64 KiB linked-reading options); `scripts/lib/boundedInput.ts` refuses before reading. `npm run intelligence`, `intelligence:mcp` (startup document, `--analysis`, and `diagramcloud_propose_project` / `_design` arguments above 512 KiB return `isError`), `atlas`, `design` (`--delta` now read before the output folder is created), concept preview/host, linked reading, explain and `package:candidate` use them: "<file> is <size>: a <kind> is read up to <limit>. Nothing was read or written.", exit 1, no output. Tests: `tests/cli-input-limits.test.ts` (7). Limits: no CLI reads draw.io, Mermaid or Visio, so those limits stay App-only; the package:candidate evidence limit has no test (the command refuses a dirty tree first); App.tsx / ProjectStart.tsx keep their own 512 KiB / 4 MiB literals.
- **#154 — post-1.34 polish** (`a474742`). The export menu button reads "Meeting summary (HTML, PDF, PowerPoint)" and says what the dialog produces. The meeting summary prints the public omission notice once: the design-profile HTML figure is drawn without `omissionBase`, and the PPTX figure slide puts the notice on its own line instead of in the description that the speaker notes repeat. The `quota failure retains keyboard focus` browser test uses a real click and asserts the notice and the disabled autosave box (the old `check()` failed whenever the app turned autosave back off). Tests: `tests/public-omission-counts.test.ts` (notice exactly once per selected view in HTML and PPTX, both profiles); quota test 10/10 with `--repeat-each=5`; PPTX view slide inspected as PNG through PowerPoint. Limits: the Editable PowerPoint (`pptx.ts`) still repeats each view description in its speaker notes.
- **#155 — wave-4 findings** (`eb21200`). Four verified medium findings: Mermaid `a & b & …` lists and long `;`-separated lines parse in linear time (160k refs, 1.5 MB, in 0.17 s); draw.io deep parent chains use a one-pass three-state cycle check and memoised, non-recursive ancestor lookups (an 80k-deep chain in 0.7 s instead of a RangeError); the meeting summary PPTX model goes through `xmlSafe` and the project overview HTML escaper applies `xmlChars`; an MCP `diagramcloud_propose_mapping` suggestion records the optional `target.fingerprintBasis: "public"`, is compared with the public projection while suggested (a target that left it reads stale with its own reason), and review rebinds it to the authoring fingerprint and drops the basis; `publicDocument` never carries it and no private hash enters the reply (`docs/contracts/concept-instance-mappings.md`). Tests: `tests/wave4-findings.test.ts` (fails on the 1.34.0 source, passes with the fix). Limits: draw.io frame detection is still quadratic on a flat page of many labelled, unreferenced boxes; the time-bound tests allow 8 s.

## Not in this release

Nothing prepared for 1.35.0 was left out. Verified low findings not fixed: an empty Mermaid file and a draw.io file with a DOCTYPE both fall through to the JSON parser and show its raw error (nothing is applied); the meeting summary Paper option reads "letter" in lower case next to "A4".

## Limits kept

- Chromium is the only qualified browser. Installed VS Code/Cursor hosts, update/rollback, signing and Marketplace are not re-run for 1.35.0.
- No token forecast, queue, calendar or dispatch model; supplied usage and effort stay arithmetic over supplied inputs.
- Cross-project correspondence in linked views, separate browser windows and free docking trees are not built.
- No tag, public release, private package or deployment is claimed by this page.
