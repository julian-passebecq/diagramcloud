# DiagramCloud contributor and AI editing rules

Start with README.md, docs/ARCHITECTURE.md, docs/RESEARCH.md and docs/ROADMAP.md. Continue the existing `julian-passebecq/diagramcloud` implementation. Do not create another notebook, diagram or portfolio app in parallel.

## Documents

Use `src/core/model.ts` as the canonical contract and the generated `public/diagramcloud.schema.json` for structural guidance. Every proposed document must pass `validateDocument`; JSON Schema alone is insufficient. Keep stable IDs when renaming labels. Preserve referenced sources, synthetic/source-derived distinctions, visibility flags and image rights. Never infer that a portfolio number is a verified employer result. Do not rewrite an unretrieved CV from memory.

Add a child view by creating its node/edge memberships and positions, then assigning childViewId to a parent node. No recursive drilldown. Attach code, tables and explanations as evidence blocks; code is not executed. Synthetic data must stay labelled. Add useful input/output examples and explain the contribution, constraint or decision, rather than duplicating a vendor product description.

Observations (`src/core/realization.ts`) only enter a document through a reviewed `diagramcloud.patch`; never author one directly into the document or mark it reviewed or shareable on the author's behalf — those are the human author's decisions, made in Edit mode. Never promote a synthetic evidence block to back an observation; `validateDocument` already refuses this, but do not work around it. Keep the three meanings distinct in anything you write or generate: Planned/designed (a node's status), Observed/verified (a dated external claim), and Presented (reviewed and selected for the story or portfolio).

## Code

Keep the domain independent of React Flow. UI coordinates must not become the sole model. Public exports must call publicDocument; do not ship hidden private data in HTML comments, SVG metadata, slides, notes or bundled JSON. Authoring JSON is the explicit full backup path. Escape XML/HTML and script serialization separately. No eval or raw HTML from imported JSON.

Provider icons have their own terms. Record source and version/blob identity; never assume a repository's MIT license covers its logos. Do not crop, rotate, recolor or distort Microsoft artwork. No font binaries in source or delivery archives.

Before proposing a completed change, run TypeScript, unit tests, production build and browser tests. Test drilldown with the parent retained, rejected imports without mutation, public redaction, storage failures/conflicts and exported HTML without a network. Inspect exported PPTX visually as well as checking that it is a valid ZIP. Use a feature branch; do not overwrite another branch or assert that CI passed without reading its result.

## Current limits (1.16.0)

Shipped and tested: measured shared export scene with box-avoiding orthogonal routes, icon registry, save/recovery tests, AI change preview, JSON Patch revision guards, visual story composer, visual table/transformation/source editors, realization in exports and the verification receipt. Diagram Design mode (`src/export/design/`) is a rendering of the public document and ViewSpec in diagram-design's visual grammar (MIT, attributed in THIRD_PARTY_NOTICES.md): never a second model, no copied code, icons or fonts, no network. The sequence figure's order is derived from connections and says so; never present it as timing. The chart figure prints its block's provenance; never drop or soften it. The status board shows the designed status and says so; never present it as observed. The architecture delta (`src/export/design/delta.ts`) compares two versions of one project by stable ID, both public; it never imports, and never claims order, downtime or cause. `view.design` and a `diagramcloud.design-brief/1` hold presentation only (figure type, at most two focal IDs that must be in the view, theme, caption); a brief is applied through the import review and never changes components, connections, basis or observations. An agent writes a brief, never the document (`skills/diagramcloud-design/SKILL.md`). Lens facts (`src/core/atlas/lens.ts`) are runtime pointers in a snapshot, never nodes, edges, design status or observations; do not reimplement Lens (no commit graph, no churn), and never treat lines changed as productivity. `datapass.lens.minimap/1` still lives on an unmerged tern-vscode branch: keep the reader tolerant and re-check it when Lens merges. There is no Brain format yet; `contextRefs` is the slot for it. The Technical Manual (`src/export/manual.ts`) is a public export: it takes its specs from `viewSpec(input)` so omissions are reported, never from an already-redacted copy. The MosaicStudio adapter (`src/export/concept.ts`) produces `datapass.concept-spec/1`, owned by datapass-mosaicstudio: tests check it with the owner validator vendored in `tests/contracts/mosaicstudio/` (re-vendor, never edit); it never emits a `lake` and never invents sources. A galaxy map is read, never written: Claude Control owns `galaxy.json`, and a real Galaxy atlas (private repositories) is generated locally with `npm run atlas`, never committed. Blueprint and Editorial are renderings (`src/export/styled.ts`) of the same view spec and export scene, never a second model; keep them static, offline and free of third-party branding. Perspectives and the renderer-neutral view spec live in `src/core/viewspec.ts`: never add facts there, and report a missing perspective as partial / unknown / unsupported rather than inventing a view. The project atlas (`src/core/atlas/`, CLI `npm run atlas`) takes membership only from an explicit manifest, DataPass project file or reviewed Add repository; each repository keeps its own revision in a snapshot (never invent a single project SHA), and a node or edge `basis` is only `planned`, `static-source` or `unknown` — observed facts still enter only as reviewed observations. The repository scanner (`src/core/scan/`, CLI `npm run scan`) is deterministic: keep every item and link backed by file:line evidence and a confirmed / inferred / possible confidence, never read secret files or copy environment values, and never present a scan as Observed/verified. The AtlasNote cheatsheet export (`src/export/atlasnote.ts`) must keep passing AtlasNote's own validator, vendored unchanged except for its asset registry in `tests/contracts/atlasnote/validation.mjs` (refresh it from AtlasNote when its cheatsheet schema changes; never edit AtlasNote from here). draw.io, Mermaid (flowchart, architecture-beta) and Visio (.vsdx) imports live in `src/core/interchange/`, the draw.io export in `src/export/drawio.ts` (through publicDocument, round-trip tested) and always report what they drop; keep them adapters that create a new reviewed project, never silent approximations. Keep these limits explicit until code and tests change them: the layout button is a grid, not a graph auto-layout engine; no binary .vsd, no Lucidchart native file and no Visio export; the canvas does not route edges from the export scene; only Chromium is qualified; the DataPass folder handle is not persisted. Post-V1 candidates are in docs/ROADMAP.md; release qualification is in docs/RELEASE.md.
